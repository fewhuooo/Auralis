# StudyCore (学核) 跨平台智能生产力中枢 - 详细产品需求文档 (PRD)

**项目名称**：StudyCore (学核)
**文档版本**：V2.0
**更新日期**：2026-05-08

> [!IMPORTANT]
> **V2.0 重大变更**：移除 OpenClaw Sidecar 架构。AI 能力全部由 Spring Boot 后端通过 LangChain4j 直连云端大模型 API 实现，前端不再直接调用任何 AI 接口，统一走后端 `/api/ai/*` 端点。

---

## 1. 产品概述与核心价值

### 1.1 产品定位
StudyCore 是一套由云端大模型（如 Claude / GPT / DeepSeek / Ollama 本地模型）驱动的、以"知识块"和"任务块"为底层数据结构的校园生产力系统。它突破了传统笔记应用和任务管理工具的界限，将 AI 深度融入到多端（手机、平板、电脑）的物理特性中。

### 1.2 核心价值
- **场景化分工**：手机负责碎片化检索与捕获，平板负责沉浸式阅读与手写推导，PC负责重型资产编排与代码执行。
- **端到端自动化**：利用云端大模型的推理能力，通过 Spring Boot 后端统一编排，实现从知识获取、整理归档到任务规划的全链路闭环。
- **知识库自生长**：通过主动搜索和自动补全，用户的个人知识库（Personal Context）能够在使用过程中不断丰富和完善。

### 1.3 架构核心原则
- **后端集中式 AI**：所有 AI 推理、RAG 检索、Embedding 生成均在 Spring Boot 后端完成，前端无需关心模型选型和密钥管理。
- **模型无关性**：后端通过 LangChain4j 的 OpenAI 兼容接口抽象层，支持热切换不同大模型供应商（OpenAI / Anthropic / DeepSeek / Ollama 本地部署等），无需修改业务代码。
- **轻量客户端**：移除 Sidecar 进程守护，Tauri 桌面端纯粹作为 Web 容器，启动更快、内存占用更低。

## 2. 全端通用底层逻辑："块"生命周期 (Block Lifecycle)

StudyCore 的所有信息和任务均以"块 (Block)"的形式存在并流转。

| 产生路径 | 交互终端 | AI 参与深度 | 最终形态 |
| :--- | :--- | :--- | :--- |
| **碎片问答** | 手机端 | 后端调用大模型联网搜索 + 语义提取重组 | 若本地库中无对应知识，则自动生成"知识块"补全入库。 |
| **文档导入** | 电脑/平板端 | 后端语义切片 (Chunking) + 逻辑聚合 | 将长篇长文、百页 PPT 按逻辑结构聚合为包含定义与代码的"分子块"。 |
| **手写录入** | 平板端 | 后端视觉 OCR + 格式转化 | 将平板自由手写笔迹转化为规范的 LaTeX 公式或 Markdown 代码块。 |
| **任务规划** | 电脑端 | 后端多步推理 + 目标拆解 | 将宏观大目标（如"蓝桥杯算法集训"）粉碎为可执行、可追踪的"任务块"。 |

## 3. 详细功能模块设计

### 3.1 手机端 (Mobile)：知识猎人与智能哨兵
**定位**：利用手机的便携性，主打碎片化时间利用、随时随地的知识捕获与状态同步。
**核心功能模块**：
1. **全能知识唤醒 (Smart Inquiry)**
   - **交互方式**：支持语音输入、快速文本输入、全局悬浮窗唤醒。
   - **RAG 本地检索**：接收到指令后，前端将请求发送至 Spring Boot 后端，后端优先调用 `Personal Context` 语义搜索本地知识库（Milvus 向量检索）。若命中，则以"分子块"的形式展示上下文脉络。
   - **自动补全与自生长**：若本地知识库无匹配内容，后端自动调用大模型进行推理，获取答案后主动询问用户："是否需要将此知识点转化为知识块并归档至 [对应学科]？"同意后自动完成入库。
2. **轻量状态同步屏 (Status Monitor)**
   - **时间流展示**：以 Timeline 形式展示由 PC 端排好的当日任务流。
   - **无感番茄钟**：支持番茄钟状态的三端毫秒级同步，手机锁屏界面或灵动岛实时显示当前专注状态，不强制阻断用户其他紧急操作。

### 3.2 平板端 (Tablet)：多模态伴读与手写转化
**定位**：利用平板的大屏和手写笔特性，主打深度文献阅读、公式推导与图形化记忆。
**核心功能模块**：
1. **PDF 智能伴读 (PDF Copilot)**
   - **即时问答**：用户在阅读课件、文献 (PDF/EPUB) 时，可直接使用手写笔圈选文字、复杂公式或图表进行询问。
   - **多模态解析**：前端将圈选内容上传至后端，后端借助大模型的视觉与逻辑推理能力，精准解析图表数据关联和公式含义，并结合文档上下文给出解释。
2. **手写笔迹"复活" (Handwriting Resurrection)**
   - **无界草稿纸**：提供无限画布供用户自由推导公式、绘制思维导图或架构图（如 JVM 内存模型）。
   - **一键结构化引擎**：套索圈选草稿内容后，前端将图片上传至后端，后端调用大模型自动将手写文字转为标准 Markdown 文本，将凌乱的手写公式转为标准 LaTeX 代码，并允许一键封装为"知识块"存入数据库。

### 3.3 电脑端 (PC)：全能中枢与逻辑工厂
**定位**：利用 PC 的算力与键盘输入优势，主打重度任务规划、资产编排与复杂环境模拟。
**核心功能模块**：
1. **功能全聚合基座 (Central Hub)**
   - 完整包含手机端的"检索/补全入库"逻辑与平板端的"文档解析/伴读"逻辑（除直接手写输入外）。
2. **重型资产智能编排 (Asset Orchestration)**
   - **文件粉碎机**：用户导入庞大的 PPT、PDF 考纲或长视频课程，前端将文件上传至后端，后端运用大模型的任务规划能力，自动提取核心知识点，将其拆解并转化为结构化的"任务块"和"知识块"。
3. **辅助式排期副驾 (Scheduling Copilot)**
   - **智能拖拽排课**：用户将"任务块"拖拽至时间表的空档期时，前端调用后端 AI 排期接口，后端将结合历史学习数据，实时进行"脑力负荷"预估与"认知容量"预警，避免过度排期。

## 4. 技术栈与架构设计

### 4.1 整体架构图景
StudyCore 采用**前端轻量呈现、后端集中智能、云端模型驱动**的架构设计：

```
┌───────────────────────────────────────────────────────────┐
│                    前端客户端 (Vue 3)                        │
│  ┌──────────┐  ┌──────────────┐  ┌─────────────────┐     │
│  │ PC/Tauri │  │ Mobile/Uniapp│  │ Tablet/Uniapp   │     │
│  └────┬─────┘  └──────┬───────┘  └────────┬────────┘     │
│       │ HTTP/WS       │ HTTP/WS           │ HTTP/WS      │
└───────┼───────────────┼───────────────────┼──────────────┘
        │               │                   │
        └───────────────┼───────────────────┘
                        │
           ┌────────────▼────────────┐
           │  Spring Boot 后端 (:8080) │
           │  ┌────────────────────┐ │
           │  │ LangChain4j 编排层  │ │
           │  │ AiServices / RAG   │ │
           │  └───────┬────────────┘ │
           │          │              │
           │  ┌───────▼────────┐    │
           │  │ OpenAI 兼容适配层│    │
           │  └───────┬────────┘    │
           │          │              │
           │  ┌───────┴──────────┐  │
           │  │ PostgreSQL│Milvus│  │
           │  │ Redis     │SQLite│  │
           │  └──────────────────┘  │
           └────────────┬───────────┘
                        │ HTTPS
           ┌────────────▼────────────┐
           │  云端 LLM API            │
           │  OpenAI / Claude /      │
           │  DeepSeek / Ollama      │
           └─────────────────────────┘
```

### 4.2 前端技术栈 (Client-Side)
- **核心框架**：Vue 3 (Composition API) + TypeScript
- **跨平台方案**：
  - **PC端**：Tauri 2 (基于 Rust，纯 Web 容器模式，不再承担 Sidecar 管理职责)。
  - **手机/平板端**：Uni-app (一套代码编译为 iOS/Android App 及小程序)。
- **状态管理**：Pinia
- **UI 组件库**：根据平台定制（如 PC 端使用 Element Plus / Naive UI，移动端使用 uView 或 Vant）。
- **AI 交互**：前端不直接调用任何 LLM API，所有 AI 请求统一通过后端 `/api/ai/*` 接口。

### 4.3 后端与通信层 (Backend & Communication)
- **后端服务**：Spring Boot 3.x (Java 17 LTS)，负责业务逻辑流转、用户数据管理、**AI 编排与推理代理**。
- **AI 编排框架**：LangChain4j —— Java 原生 LLM 编排框架，提供：
  - `AiServices` 声明式接口：通过注解定义 AI 能力（问答、提取、排期等）。
  - `ContentRetriever` / `EmbeddingStore`：RAG 检索增强生成。
  - `Tool` 注解：Agent 工具调用（知识库搜索、任务创建等）。
  - `ChatMemory`：对话上下文管理。
- **模型适配**：通过 LangChain4j 的 OpenAI 兼容层 (`langchain4j-open-ai`)，可接入任意 OpenAI API 格式的模型服务商，包括：
  - **OpenAI** (GPT-4o / GPT-4o-mini)
  - **Anthropic Claude** (Claude 3.5 Sonnet / Opus)
  - **DeepSeek** (DeepSeek-V3 / DeepSeek-R1)
  - **Ollama** (本地部署 Llama 3 / Qwen 等开源模型)
- **实时通信总线**：WebSocket 配合 Redis Pub/Sub 订阅发布机制，实现多端状态（番茄钟、新知识块入库等）的毫秒级实时同步。
- **数据库**：
  - **关系型**：PostgreSQL (存储用户信息、系统设置、任务基础数据)。
  - **向量数据库**：Milvus (用于 RAG 架构，存储知识块的向量 Embedding，支持超大规模语义检索)。

### 4.4 AI 能力实现方式 (AI Layer — 后端 LangChain4j)
- **智能问答**：`StudyCoreAssistant` AiService —— 带 RAG 检索的知识问答，流式 SSE 返回。
- **文档切片**：`KnowledgeExtractor` AiService —— PDF/PPT 语义切片，输出结构化知识块 JSON。
- **任务排期**：`TaskScheduler` AiService —— 基于历史负荷数据的认知容量预测与排期建议。
- **多模态解析**：通过支持 Vision 的模型，解析图表、公式截图。
- **RAG 检索引擎**：LangChain4j `EmbeddingStoreContentRetriever` + Milvus 向量库，构建个人知识库问答流水线。

### 4.5 部署与安全架构 (Deployment & Security)
- **模型 API 密钥管理**：API Key 存储在后端 `application.yml` 或环境变量中，前端不接触任何密钥。
- **后端部署**：Spring Boot JAR 部署在服务器或本地开发机，前端通过 HTTP 连接。
- **安全隔离**：前端 → 后端 → 云端 LLM 的三层隔离，避免密钥泄露和 Prompt 注入。

## 5. 项目演进与阶段规划

- **Phase 1: 基础设施搭建** (跨平台框架初始化、账号体系、基本的块存储与双向同步)。
- **Phase 2: 后端 AI 核心接入** (Spring Boot + LangChain4j 直连云端大模型 API，实现 RAG 检索与问答补全逻辑)。
- **Phase 3: 多模态伴读** (实现平板 PDF 伴读与手写公式 LaTeX 转换，通过后端 Vision API)。
- **Phase 4: 编排与预警** (完善 PC 端的任务拖拽排期与脑力负荷预警算法)。

## 6. 功能开发顺序与实施路径 (Functional Development Sequence)

为了保证"块"流转逻辑的稳健性，StudyCore 将按照"底层数据 -> 核心交互 -> 复杂业务 -> 跨端多模态"的顺序进行功能开发。

### 第一阶段：底层基座与数据体系构建 (Core Foundation)
本阶段的核心是建立坚实的后端服务及"块"的数据结构。
1. **基础环境搭建**：初始化 Spring Boot 工程和数据库结构 (PostgreSQL 用于元数据，Milvus 用于向量检索)。
2. **块系统 (Block System) CRUD**：实现"知识块"和"任务块"的创建、读取、更新和删除接口，确立块之间的基础关联模型。
3. **实时通信管道建立**：搭建基于 WebSocket + Redis Pub/Sub 的消息推送服务，打通跨端状态同步的底层能力。
4. **统一认证体系**：完成多端统一的用户注册、登录鉴权模块。

### 第二阶段：后端 AI 集成与手机端检索 (Backend AI & Mobile RAG Pipeline)
本阶段聚焦核心的 AI 交互链路，打通"提问->检索->补全->入库"闭环。
1. **跨端框架初始化**：基于 Uni-app 构建手机端骨架，基于 Tauri 构建 PC 端骨架。
2. **后端 LangChain4j 集成**：配置 OpenAI 兼容 Chat Model / Embedding Model，对接云端大模型 API。
3. **RAG 检索链路**：后端实现 `EmbeddingStoreContentRetriever` + Milvus 向量检索，开发手机端"全能知识唤醒"UI，前端调用后端 `/api/ai/chat` 进行 RAG 问答。
4. **自动补全与入库机制**：后端实现当向量库无匹配时调用大模型推理，并将答案格式化为"知识块"写入数据库，同时通过 WebSocket 将入库状态推送至其他终端。

### 第三阶段：PC 端重型编排与任务流转 (PC Orchestration)
本阶段主攻长文本处理与复杂的任务调度逻辑。
1. **PC 端聚合基座**：在 Tauri 桌面端复刻手机端检索能力，并完成本地库的可视化管理界面。
2. **文档语义切片引擎**：前端上传文件至后端 `/api/ai/ingest`，后端调用 DocumentParser (Tika) + DocumentSplitter 进行语义切片 (Chunking)，批量生成"分子块"。
3. **智能任务拆解**：开发重型目标规划功能，后端利用大模型多步推理将复杂考纲或长文自动拆解为颗粒度适中的"任务块"。
4. **时间流与排期副驾**：开发 PC 端 Timeline 视图，支持拖拽"任务块"，后端提供基于历史负荷的"脑力负荷"预警 API。
5. **轻量状态回传**：将 PC 端排好的当日时间流与番茄钟状态，通过 WebSocket 下发至手机端"轻量状态同步屏"展示。

### 第四阶段：平板端多模态与手写生态 (Tablet Multimodality)
本阶段攻克视觉解析与手写识别难题，完善平板特有体验。
1. **PDF 智能伴读器**：在平板端实现 PDF 渲染引擎，支持文本和区域套索圈选。
2. **多模态视觉交互**：前端将圈选区域截图上传至后端，后端调用支持 Vision 的大模型接口，实现对图表或复杂公式的语义解析与问答关联。
3. **无界手写画布**：开发平板手写草稿纸功能，捕捉和记录用户笔迹与绘制结构。
4. **手写结构化转化**：前端上传笔迹图片至后端，后端利用 OCR 与视觉模型，实现将手写公式一键转为 LaTeX、手写草稿转为 Markdown 的转化引擎，并将转化结果封装入库。
