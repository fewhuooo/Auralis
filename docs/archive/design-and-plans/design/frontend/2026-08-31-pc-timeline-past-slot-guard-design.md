# PC 时间轴过去时段保护设计

更新时间：2026-08-31

文档状态：已批准，待实施

范围：PC Dashboard 与 Timeline 的任务排期交互

## 目标

防止用户将任务排到已经过去的时间轴时段，同时不改变现有的到期自动转换规则：已过排期的既有任务仍由 Store 自动完成；无排期且过截止的任务仍清除截止时间并进入未排期。

## 已批准交互

- 以客户端操作当刻为准，目标 `scheduledAt` 早于当前时间即为过去时段；等于或晚于当前时间可以提交。
- Dashboard 与 Timeline 的拖放排期、周视图按天排期、已排期任务换位都在调用 Task API 前使用同一 Store 校验。
- 目标时段已过去时，操作拒绝、任务保持原位置和状态、不发 API 或离线 mutation，并由既有页面错误反馈显示“不能排期到过去的时间”。
- 不自动改到下一个可用时段；周视图按天排期若其默认时段已过去，同样拒绝。

## 实现边界

- 在 `useTaskStore` 提取一个只负责比较目标时间与当前时间的校验，供 `scheduleTask`、`scheduleTaskToDay` 与 `rescheduleTask` 共用。
- 保持 `scheduledAt` 的现有 UTC ISO 归一化和服务端原子换位接口；本轮不修改后端或 OpenAPI。
- 新增回归覆盖过去时段拒绝、未来时段允许、换位目标拒绝，以及页面从 Store 异常路径保留错误反馈。

## 验收条件

1. 三条排期入口都不能创建或移动到过去的时段。
2. 被拒绝时本地任务、服务器请求和离线同步队列均不改变。
3. 当前或未来时段仍可按既有行为排期或换位。
4. PC 自动测试、类型检查与构建分别通过；Tauri GUI 拖放保留人工验收。
