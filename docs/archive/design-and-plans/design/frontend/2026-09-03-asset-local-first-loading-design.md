# 资产库本地优先加载设计

日期：2026-09-03

## 目标

资产库优先展示用户/设备隔离的本地资源，云端不可达时保持本地可用；云端结果到达后写回本地 repository，并以最新本地投影重建资产树。

## 根因

资产库将学科、资料、知识块和任务读取串行绑定为一个全局 loading 状态，并只在首次读取结束时构建一次 `rootNodes`。PC Store 已转为本地返回、远端后台刷新后，后台写回 Pinia/repository 的结果不会触发资产树重建；任一读取未收敛时也会阻塞全局 spinner。

## 设计

1. `Asset/index.vue` 将树构建提取为无副作用的 `rebuildAssetTree()`：它仅从当前 Store 的本地投影构造 `rootNodes`。
2. 首屏加载并行触发四类资源的本地 hydration；各项完成或失败后都继续构建现有本地树，并在本地阶段结束时关闭 spinner。局部失败仅记录为降级信息，不清空其他资源。
3. 资产库订阅 Subject、Source、KnowledgeBlock 与 Task 的 Store 投影。任一 Store 的后台云端刷新写回本地并更新投影后，页面重新调用 `rebuildAssetTree()`，不重开 spinner。
4. Store 仍是云端到本地的唯一同步边界：远端 DTO 通过既有 `cache`/repository 写回，本地存在未同步 mutation 时继续由 outbox 合并/保护。资产库不直接写 API、不覆盖 pending 本地写入。

## 降级与错误处理

- 云端读取失败：保留已构建的本地树，记录可诊断警告，不显示永久加载状态。
- 本地某类资源读取失败：仍使用其他三类资源构建树；空树显示“暂无数据”，而非 spinner。
- 首次无本地数据：先显示空态；远端刷新抵达并缓存后，订阅触发重建。

## 验收

- 资产库首次进入不会因云端慢/失败而持续显示 loading。
- 有本地缓存时立即显示树。
- 后台云端返回新增、更新或删除时，树自动更新且不重新转圈。
- 已有的 pending 本地资源不会被远端刷新从树中丢失。
- 自动测试覆盖本地优先、降级、后台重建的结构契约；PC 回归、类型检查、静态检查与生产构建通过。真实弱网浏览器/Tauri 验收另行记录。
