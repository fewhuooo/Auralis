## 已确定的要求

- 用户选择移除失效的旧复习自动生成逻辑，并要求重建复习页面和逻辑。
- 新入口归属于学科工作区侧栏，与材料、总览、知识库同级，内容范围为当前学科。
- 用户要求每个知识块在本轮第一次选择评分时计算下次复习日期，后续重复仅用于本轮巩固；此处指每轮第一次非 SKIP 评分，不是该知识块一生只调度一次。
- 用户于 2026-10-08 明确卡片反馈只提供“下一个”和“记错了”。展开正文后分别提交 GOOD / AGAIN；展开前仅回忆与揭晓，不评分。
- 同日后续要求进一步研究：复习前置认识/模糊/忘记了，完整信息核对仍为下一个/记错了；模糊末尾独立回忆一次，失败转学习。学习三段式和正式事件写入时点尚待方案确认，暂不继续修改交互代码。
- 同日最新纠正：复习初选即计算下次日期；展开后记错还须重新计算并纠正初选结果。此要求覆盖上方原先每轮仅首次计算及先核对后提交的安排。下一个仅确认初选；同次纠正的持久化与统计方案尚未实施。
- 学科侧栏另增加独立“统计”入口，统计当前学科的学习情况，与复习页并列。
- 用户明确专注时长与轮次只在个人页显示，学科统计不分配专注记录。
- 用户明确本轮临时练习仅保留本机切换页面后的恢复能力；刷新、重启及跨设备不恢复本轮练习。
- PC / Service 为本轮功能范围；其他功能清单仍按用户要求逐项确认。
- 保留已有任务、知识块、ReviewState 和不可变 ReviewEvent；退役旧生成器不删除历史业务数据。

## 流程选择

采用 **知识块自评**：标题用于回忆，展开知识正文后选择“下一个”或“记错了”；复用现有 GOOD / AGAIN 评分和服务端调度，首次学习与后续到期复习形成同一闭环。已有知识块、评分接口和历史继续复用。

另一种方案是 **题目练习**：先生成题目，作答后判分，再安排复习。当前知识块只有正文、没有题目/答案模型或判分协议；该方案还需明确出题范围、答案保存、判分失败及 AI 调用规则，范围大于下面的知识块方案。

用户进一步讨论不背单词式分组巩固，并明确采用首次选择时调度一次的规则。下文按知识块回忆与两项反馈整理，分组数量和统计指标沿用已批准范围；业务验收仍按实际证据单列。

## 参考研究与采用边界

- [不背单词官网](https://bbdc.cn/) 确认按记忆效果动态安排学习；[开发者更新日志](https://apps.apple.com/us/app/不背单词-真实语境学英语单词/id698570469) 确认分组复习、学习/复习后的拼写分别可配置，且 2025 年调整过复习算法。
- [2022 年机制分析](https://pdf.hanspub.org/ae20220700000_69509379.pdf) 描述旧版当次重复检测及逐词跨天调度；其中连续答对四次、答错清零属于旧版观察，不能作为现行规则或本项目的强制参数。
- 本方案借鉴分组回忆和本轮巩固，由 Auralis 现有 FSRS_LITE 调度计算日期，不宣称复现不背单词未公开的算法。

## 当前实现证据

- `Auralis-PC/src/views/SubjectWorkspace/index.vue` 已有 72px 的学科内 tier1 侧栏，中心区使用 centerView 切换；可增加 review 子视图，沿用 `/subject/:id`，无需新增全局导航。现有 query view 模式可扩展为 `?view=review`。
- `Auralis-PC/src/views/Timeline/index.vue` 挂载时调用 checkSpacedRepetition，读取知识块 reviewAt，创建普通 Task 并将 reviewAt 顺延三天。现行 KnowledgeBlock DTO 和 mapper 不含 reviewAt，更新也不持久化该字段，这条路径已经断开。
- PC 的 useReviewApi / useReviewStore 有 due、event、history 包装，但没有页面消费者、学科与会话归属保护、请求乱序保护或离线复习事件存储。
- Server `/api/reviews/due` 只读已有且到期的状态；新知识块没有状态，非 SKIP 首次评分才创建，baseVersion 为 0。
- 当前 due 查询先取全账号最早 200 条，后过滤活动知识块；接口没有学科过滤和分页。前端再筛学科会漏项，不能作为完整学科页实现。
- ReviewEventView 不含事件 afterState、最终状态版本或下次复习时间；history 按客户端 reviewedAt 排序，不能由历史推算当前状态。
- `/api/reviews/events` 已支持完整载荷幂等回放与版本校验；`/api/reviews/history?knowledgeBlockId=...` 已提供所选活动知识块的历史。SKIP 只记事件，不修改或创建 ReviewState。
- 现行 `/api/stats/overview` 和 `/api/stats/weekly` 是用户级聚合，后者固定连续七天、使用 UTC 日期，没有学科筛选；不能直接投影为学科统计。

上述来自两个 Luna 只读执行 Agent 的当前代码检查，未运行测试、真实 HTTP 或 GUI，也未修改业务代码。

## 页面与交互

### 学科入口

- 在学科内 tier1 侧栏加入“复习”，点击切换中间区域到独立 SubjectReviewPane；沿用现行色彩、文字和按钮体系。
- 同栏加入“统计”，中间区域显示 SubjectStatsPane，沿用 `/subject/:id`；不新增全局导航。
- 支持 `?view=review` 和 `?view=stats` 刷新直达；切学科后视图使用新的 subjectId，旧学科响应不能改变新页面。
- SubjectWorkspace 只负责入口、视图切换和传递当前学科，列表、卡片和复习状态放在专门的组件与既有 Review Store 中。

### 列表与状态

- 从当前学科的活动知识块投影提供标题和正文，将知识块 ID 与完整的服务端学科复习状态关联。
- 页面提供“新学习”“待复习”“已安排”的切换与数量。未有状态是新学习，dueAt 已到是待复习，未来 dueAt 是已安排。
- 分页状态读取全部成功前，不能把未知状态当作新卡或将加载失败显示成零条。知识块在本地已删、移到其他学科或尚不存在时不显示旧关联。
- 已安排列表用于查看下一次时间和该知识块历史；默认学习队列由新学习与到期内容组成。
- 空状态分别说明没有知识块、没有待复习内容或需要连接服务；请求错误有明确重试入口。

### 卡片复习

- 新学习和待复习均按组练习，草案提供每组 5 / 10 个知识块、默认 5 个；数量为本项目建议，不是不背单词默认值。
- 展示标题与进度，先回忆，再点击“展开内容”；正文复用当前 Markdown / 数学公式渲染。
- 展开后只提供“下一个”（GOOD）与“记错了”（AGAIN）两项反馈。展开正文不生成评分事件。
- 首次评分用 baseVersion=0；已有状态用读取到的真实 version。下次时间由服务端 EventResponse.state 决定，客户端不自行顺延三天。
- 每个知识块本轮首次评分成功后，固定本轮已正式评分标记及服务端结果。“记错了”放到本轮练习队尾，“下一个”完成本轮该卡；后续本轮再次反馈只更新练习进度，不再调用 events、不更新 dueAt、reps、lapses 或正式历史。
- 后续巩固中仍选择“记错了”则继续进入练习队尾；选择“下一个”则结束该卡巩固。可以主动结束本轮，不强制规定连续答对四次或无限完成全部内容才能退出。
- 历史评分、已存在的待确认请求以及其他端继续使用现行 ReviewRating 契约；保存过的 HARD / EASY / SKIP 事件保持原值、历史显示与幂等重试语义。
- 下一轮到期复习可以再提交新的正式评分。进行中的组大小选择用于下一组，不重建当前队列、卡片或本轮评分标记，所选大小在切页后保留；切换页面保留本轮，明确结束本轮、刷新或重启后从服务端最新状态重新建立队列，不把已正式评分的卡片再次当作新学习。未提交成功的请求不能进入仅练习阶段。
- 所选卡片可查看复习历史，展示评分、时间和耗时。历史范围明确为所选知识块，沿用已有单块 history 接口。
- 提交成功后才推进卡片和刷新状态；没有成功确认时保留当前卡片及选择，提供明确反馈。
- 完成一组后展示本轮处理的不同知识块数和首次反馈分布，并列出仍需巩固项与已获得的下次安排；本轮处理完成不宣称永久掌握。后续练习点击不重复增加正式复习量。

### 本机切页恢复

- 在既有 Review Store 中按当前账号 / 设备 / 会话代际及 subjectId 保存本轮内存状态；离开复习页不等于结束本轮。当前应用运行期间切到材料、统计、其他页面或其他学科，再返回原学科时可继续其本轮。
- 保留组大小、卡片队列与顺序、当前卡片、正文展开状态、待巩固项、已完成/跳过项、首次正式评分成功标记和本轮结果；恢复后已经正式评分的卡片仅做巩固，不重复提交或计算日期。
- 已发出的正式评分由 Store 持有同一 clientEventId 与不可变载荷。切页时不因组件卸载丢失该请求；响应可以结算对应的有效内存轮次，但不能改变当前其他学科页面。失败或结果未知时保留原请求，返回后原样重试，不能生成另一条评分。
- 恢复时核对知识块活动状态与当前学科归属，已删除或移出的卡片退出该轮；读取更新的服务端状态不会抹掉本轮已正式评分标记。首次尚未确认成功的卡片仍按原幂等请求确认结果。
- 明确结束本轮后停止该轮练习；退出登录、切账号或会话代际变化清除本轮缓存。刷新、重启后重新读取服务端状态，不恢复本轮队列；本轮内存不写 localStorage、SQLite 或同步接口。

### 学科统计

统计范围按学科资料、知识块、复习和任务整理；用户进一步明确专注只留在个人页。已批准的具体页面指标与交互如下。

两种数据接入方式：仅用现有本地投影可快速展示当前资料/知识块/任务数，但不能得到完整跨设备的复习与历史趋势；推荐新增服务端学科聚合读取，统一展示已同步的统计，本地未同步变化不直接叠加。

| 区域 | 推荐指标与口径 |
| --- | --- |
| 学科概况 | 当前活动材料数、知识块数、任务数；材料按 FILE / TEXT / URL 区分，不把尚未同步的本机记录算入服务端总量 |
| 复习进度 | 未学习（活动 KB 无 ReviewState）、待复习（dueAt <= 查询时刻）、已安排（dueAt > 查询时刻）；三者相加应等于服务端活动 KB 总数，不以全用户 due 的前 200 条计算 |
| 近期趋势 | 最近 7 / 30 天每天正式评分的不同知识块数、正式评分次数和新增知识块数；SKIP 与后续本轮练习不算完成复习，同一天同卡多轮评分可产生多次评分但只计一个知识块 |
| 记忆反馈 | 所选时间范围正式非 SKIP 事件中忘记 / 困难 / 记得 / 熟练的次数与比例；表示评分分布，不包装成长期掌握率 |
| 任务情况 | 当前活动 TODO / IN_PROGRESS / DONE / CANCELLED 数量；日期趋势仅表示当前仍为 DONE、completed_at 落在当日的任务数，沿用已完成软删除任务的统计，不称作历史完成转换次数；已重新打开任务的旧完成时间无法恢复 |

- 统计页不创建第二套复习调度器或修改知识块正文；状态卡可进入同学科的复习对应列表。
- 7 / 30 天趋势使用请求时的系统 IANA 时区划分本地自然日，服务端返回采用的时区与查询时刻；新接口不改变既有 UTC weekly 契约。
- 一次响应提供完整统计，页面明确加载、真实零值、加载失败与重试；失败不能以 0、旧账号或旧学科数据代替。保留旧成功数据时必须提示未能刷新。
- 复习正式评分成功、同步完成或切换统计范围后重新读取；请求固定账号、学科、时间范围和时区，迟到的旧请求与 finally 不修改新页面。
- 复用现行卡片、字体、Sage 色彩和轻量 CSS / SVG 趋势展示；当前 PC 未发现专用图表依赖，本方案不新增图表包。

## 服务端与数据边界

- 推荐新增只读 `GET /api/reviews/states?subjectId=...&cursor=...&limit=...`，返回当前用户、当前学科活动知识块的已有 ReviewState，包括到期及未来状态，使用现行 cursor page 包装。
- 查询必须在分页前过滤 owner、活动 Subject / KnowledgeBlock 和 subjectId，按稳定键排序；cursor 与查询范围一致，非法、跨范围或跨 owner 游标不能扩大读取。
- PC 读取所有状态页后才完整分类；不会由前 200 条缺少某 ID 推断“从未学习”。新建但仍未同步的知识块不能直接被当作服务器已存在；提交失败需要区分待同步与真实不存在，并允许显式同步后重试。
- 保持 `/due` 的仅到期含义；评分及单块历史复用现有接口和不可变事件。新页面无需改变调度参数、现有表、迁移、核心 Sync 资源类型或专注统计口径。
- 统计推荐新增只读 `GET /api/stats/subjects/{subjectId}?days=7|30&timeZone=<IANA>`，返回该活动学科的概况、复习状态计数、逐日趋势、正式反馈分布和任务情况；具体 DTO 在实施计划中按现行代码定稿。
- 学科聚合必须先校验 owner 与活动 Subject，所有关联查询保持用户隔离，分别聚合事件/资料/任务后组合，避免多表联接乘法导致重复计数。知识块和任务当前归属与历史事件发生时归属不同，指标按当前归属解释。
- 复习状态三类数量在同一查询快照中分类聚合，接口中的学科概况与状态计数保持一致；不能分别读取旧总数和新状态数后拼成一份貌似完整的统计。
- 近期评分可以按事件 before_state 是否为 null 区分该知识块第一次正式学习与后续正式复习，不能以 baseVersion=0 区分，因为首次创建状态的版本本身也是 0。SKIP 不参与这两类计数；仅有 SKIP 的无状态知识块仍属于“尚未正式评分”，不声称用户从未阅读它。
- 不给现行 events 请求增加 roundId 或新的持久练习事件；PC 负责在本轮第一次正式评分后停止再次调用 events，后端仍按每个合法正式事件调度。Mobile/Tablet 已有正式评分语义不随本次 PC 分组交互改变；PC 本轮仅在当前运行期间以 Store 内存支持切页恢复。
- 专注统计继续沿用个人页的现行聚合，本次不修改 FocusSession、专注上传或个人页统计接口。
- API 新能力必须同步 API 契约、OpenAPI 与生成类型；如 SDK 生成更新 Mobile 类型文件，只限必要生成差分，不实现 Mobile 页面变化。

## 请求与失败规则

- Review 的读取和提交绑定发起 owner/device/session 与学科代际，派发前、每个异步返回后和写回前核验；账号切换清除当前内存视图，旧结果不能进入新账号。
- 队列、状态与 history 独立处理加载、错误和请求序号；旧查询晚返回不能覆盖新选择，旧 finally 不能结束新请求的 loading。
- 一次评分先固定 clientEventId、reviewedAt、durationSeconds、rating 和 baseVersion。同次失败重试原样发送；禁止连点生成多个事件。超时不能当作未提交或成功，保留本次请求供幂等重试。
- 本轮后续练习不能修改已提交首次反馈或更换首次请求载荷；正式事件耗时只覆盖首次评分，不宣称包含未持久化的后续练习总时长。
- 版本冲突时重新读取权威状态并提示重新确认；不自动对新的状态重放另一笔评分。
- 普通离线可浏览本地知识正文，但评分及权威计划读取仍需联网。本轮不新增离线 ReviewEvent outbox，应用重启后的离线提交恢复不属于该方案验收。
- 知识块删除或移出学科后移除对应卡片，学科删除清除该轮；切学科或组件离开只暂停可见交互、保留有效本轮。迟到请求即使已在服务端完成，也不能更新当前其他账号/学科页面。

## 旧生成器退役

- 从 Timeline 挂载流程移除 checkSpacedRepetition 调用，并删除该函数。
- 不生成新的普通复习 Task，不回写知识块 reviewAt。
- 已有普通 Task 与 `[KB_ID:...]` 知识块跳转继续保留，不批量删除或改写历史任务。
