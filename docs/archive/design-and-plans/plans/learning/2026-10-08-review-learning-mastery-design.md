## 1. 目标与范围

在学科工作区内形成“首次学习 → 到期复习 → 模糊巩固或重新学习 → 长间隔验证 → 已掌握”的完整流程。达到掌握条件的知识块退出自动复习，保留历史与手动重新学习能力。

- 入口沿用学科侧栏的复习、统计，使用现行 `/subject/:id?view=review|stats`。
- 每组5或10个知识块，默认5个；复用当前页面布局，只搭必要交互框架，界面细节由用户调整。
- PC 与 Service 是功能范围；Mobile 仅接受必要的契约生成差分，其他端的既有评分调用在接口定稿时校验。
- 专注时长、完成轮次仅归个人页。
- 正式日期、学习需求与掌握状态持久化在服务端；临时轮次只在本机当前进程中恢复切页进度。
- 本轮实现 PC 与 Service 业务；用户进一步授权 Antigravity 将复习/统计配色优化到与其他页面一致。配色与业务按顺序处理，保留用户现有布局。主仓库不提交、暂存、部署或批量修改业务数据。

## 2. 已明确要求与本版建议

### 用户已明确

1. 复习初始只有认识、模糊、忘记了，先隐藏正文。
2. 认识、模糊展示完整信息后只有下一个、记错了。
3. 忘记了直接展示信息，下一步进入学习；核对记错也进入学习。
4. 模糊项在组末隐藏正文独立回忆一次；失败或核对记错转学习。
5. 初选立即参与日期计算；展开后记错须再次计算并纠正初选结果。
6. 学习采用有研究参考的三段式；掌握后停止自动复习；前三次间隔希望拉长。
7. 本机切页可恢复临时轮次；专注只在个人页；前端保持基础框架。
8. 页面分类为待学习、待复习、已掌握；GOOD、HARD、AGAIN 的首次复习间隔分别设置。

### 本版实施规则

| 事项 | 本版规则 |
| --- | --- |
| 三段式学习 | 阅读理解 → 隐藏正文回忆 → 展开核对 |
| 正常间隔 | GOOD 初始3天；三次稳定复习后分别等待7、14、30天 |
| 掌握条件 | 连续3次有效跨天复习通过，加一次至少30天后的验证通过 |
| 风险回退 | 模糊、忘记、核对记错清零连续稳定次数，历史记录保留 |
| 初始分档 | GOOD 3天、HARD 1天、AGAIN 10分钟；忘记/记错先计算10分钟后的日期，重新学习通过后从完成时刻重新起算10分钟 |
| 早期再回忆 | AGAIN 后10分钟的再回忆不增加跨天稳定次数；核对认识后安排 GOOD 初始3天，之后再推进7/14/30天 |
| 同次纠正计数 | 初选与纠正保留审计，正式复习按同次最终有效结果计1次 |
| 初选未核对 | 保存的日期保留；不确认正向掌握进度，也不毕业 |
| 内容变化 | 正文实质变化使旧内容的掌握资格失效 |

上述数值为用户已授权实施的产品默认政策，研究没有验证统一的永久掌握阈值。实施按本文件流程与验收清单执行；实际代码、命令验证与业务验收分别记录。

## 3. 页面与队列

### 复习入口

沿用当前计划卡片，显示当前学科可学习/可复习数量、组大小与开始本轮。当前用户布局作为实施基线。

页面分类与队列来源：

- 待学习：服务端尚无学习状态的知识块，以及已有状态明确要求重新学习的知识块；均可立即进入三段式学习。
- 待复习：已经学习且尚未掌握、没有需学习标记的知识块，包含未来到期与已到期项。保留下次日期，今日自动队列只选其中已到期项，按到期时间排序。
- 已掌握：退出自动队列，允许手动抽查或重新学习。

未到期的待复习项通过独立“提前练习”入口由用户选择，自动今日队列仍只取到期项。手动提前练习采用同一反馈/核对协议，按服务端当前阶段安排日期，不推进有效跨天稳定次数。

一次选择5/10个不同知识块。同卡的学习失败循环、模糊末尾巩固不占新的组名额。当前组完成后展示本轮结果，可继续下一组或结束。

尚未同步到服务端的本机知识块显示待同步，需要同步成功后进入正式学习/复习。状态分页全部成功后才分类，避免将缺页误判为未学习。

### 轮次结果

显示本组处理的不同知识块数、通过/待巩固情况、正式结果、下次日期和新达到已掌握的数量。当前未通过项保留可继续入口；服务端日期保存成功不等于本轮学习已经完成。

## 4. 复习流程

未揭晓只显示标题和回忆提示。认识指展开前能回忆核心内容；模糊指只能回忆部分或不确定；忘记了指无法回忆。

| 初选 | 立即提交 | 揭晓后的动作 | 后续 |
| --- | --- | --- | --- |
| 认识 | GOOD，按预计通过的阶段计算日期 | 下一个 / 记错了 | 下一个确认本次通过；记错纠正为 AGAIN 并转学习 |
| 模糊 | HARD，安排短期复习 | 下一个 / 记错了 | 下一个保留 HARD 与组末标记；记错纠正为 AGAIN 并先转学习 |
| 忘记了 | AGAIN，安排短期复习并标记需学习 | 下一步 | 复用已显示的完整信息为阅读阶段，下一步进入隐藏回忆 |

初选保存期间可以展示正文，推进按钮等待请求结算。初选失败或结果未知时停留当前卡片，保留原请求供重试；不提前确认进度。

下一个的作用是确认认识/模糊初选，不将模糊升级成认识。认识的正向稳定次数在核对确认成功后增加；风险反馈可立即撤销原候选资格。

### 模糊末尾巩固

1. 首次选择模糊即加入本组一次性末尾标记，即使中途记错后学过仍保留。
2. 正常卡片处理完成后，再显示该块标题，正文隐藏，先独立回忆。
3. 能回忆则展开核对，正文后仍只有下一个、记错了；无法回忆可直接进入阅读/学习。
4. 核对成功消耗该标记；失败转学习，记录失败并修正短期计划。需要时将原 HARD 纠正为 AGAIN。
5. 该次巩固不增加跨天稳定次数；成功保持原 HARD。标记仅消费一次，学习失败不会追加无限个组末任务。

## 5. 三段式学习

| 阶段 | 显示内容 | 操作与结果 |
| --- | --- | --- |
| 阅读理解 | 标题与完整正文 | 理解要点、条件、关系；开始回忆 |
| 独立回忆 | 标题/提示，隐藏正文 | 心中或口头回忆核心内容；展开核对 |
| 核对反馈 | 完整正文 | 下一个通过本轮学习；记错了返回阅读 |

首次学习直接从阅读开始。复习中忘记或记错已经显示过的正文复用为阅读阶段，避免连续展示同一完整页面。默认不要求输入答案或 AI 判断。

学习通过的业务结果：

- 首次学习：建立服务端状态，使用 GOOD 初始间隔安排3天后的第一次复习，稳定次数为0；学习完成仍是独立操作，不新增 GOOD 评分事件。
- 重新学习：解除需学习标记，安排完成时刻10分钟后的短期再回忆，稳定次数为0。
- 本轮内部重复：记录本轮练习进度，不把同日学习成功伪装成跨天 GOOD，不重复增加正式复习量。
- 学习完成需显式服务端操作，复用版本和幂等边界；不能用额外 GOOD 事件抵消先前 AGAIN。
- 末尾巩固失败后再次进入学习，需要使服务端重新处于需学习状态；已经存在的同次 AGAIN 不重复增加一次正式失败计数。

用户可结束或暂时离开；本机切页回来继续该阶段。刷新或重启后临时阶段清除，但已保存的需学习状态仍可让用户从阅读阶段重新开始。

## 6. 日期调度与掌握

### 首次与重置间隔

| 反馈档 | 初始等待 | 行为 |
| --- | --- | --- |
| GOOD / 认识 | 3天 | 首次学习通过的默认间隔；早期再回忆核对认识后回到该初始间隔 |
| HARD / 模糊 | 1天 | 组末巩固一次，后续到期再回忆 |
| AGAIN / 忘记或记错 | 10分钟 | 立即可重新学习，学习通过后重新起算10分钟，再回忆仍属短期巩固 |

初始分档用于开始或重置复习周期。已有跨天稳定进度的 GOOD 按下方7/14/30天推进；首次学习使用3天间隔，不额外增加一次三项自评。

### 无失误路径

| 当前完成点 | 下次等待 | 以首次学习通过为第0天 |
| --- | --- | --- |
| 首次学习通过 | 3天 | 第3天第一次复习 |
| 第一次认识且核对通过 | 7天 | 第10天第二次复习 |
| 第二次认识且核对通过 | 14天 | 第24天第三次复习 |
| 第三次认识且核对通过 | 30天 | 第54天最终验证 |
| 最终验证认识且核对通过 | 停止自动排期 | 已掌握 |

间隔按实际学习/复习记录加24小时的倍数计算，以服务端权威时间为准；学习以完成记录为锚点，复习以初选事件的 reviewedAt 为锚点，核对确认不因点击延迟另外平移已保存的日期。界面按用户本地时区展示。迟到复习从实际初选时刻顺延。前三次应为已到期、独立跨天且展开前尝试回忆的正式复习。

同日重复、提前练习、阅读正文、学习内部循环和末尾巩固均不推进这三个阶段。用户主动提前练习后，实际接触/练习时间需要更新，长期验证至少从最近一次记录的练习再等待30天。系统只依据已记录的行为判断，不能保证用户在系统之外未接触该知识。

### 回退

- 模糊：连续认识次数归零，安排1天后，当前组末巩固一次。
- 忘记/记错：连续认识次数归零，取消长期验证资格，立即可重新学习；失败初选/纠正计算10分钟后的日期，重新学习通过后再从完成时刻起算10分钟。
- 忘记初选的短期日期从初选时刻计算，记错纠正的短期日期从纠正时刻重新计算；两者的学习完成日期均从实际完成时刻起算。
- 学习后10分钟再回忆不算有效跨天复习。此时核对认识后安排3天，稳定次数仍为0；模糊按1天、忘记/记错按10分钟并重回学习。
- 风险后的下一次跨天认识算第一次稳定通过，此后成功间隔依次为7、14、30天。
- 初选 GOOD 可以先算7/14/30天的预计计划，核对通过后才确认对应阶段。最终验证初选 GOOD 仍保留一个暂定后续日期，核对通过后以已掌握状态退出排期；初选不能直接毕业。

### 已掌握

需要连续3次有效稳定通过、最终验证实际间隔至少30天、最终反馈为认识并核对通过，服务端事务保存成功后毕业。全程无失误最少4次正式复习，最初学习不计入。

已掌握是明确持久化状态，不用极远 dueAt 或现行 reps 猜测。不随时间推移自动重新加入队列。历史与知识正文保留，统计单独计数。

手动抽查认识且核对通过可保持已掌握；模糊恢复短期复习，忘记/记错恢复需学习状态。用户主动重新学习、正文实质修改时解除掌握，稳定进度归零并进入需学习状态；标题、来源或颜色等元信息编辑不因本方案自动抹掉掌握进度。

## 7. 同次结果纠正与计数

一次正式复习用稳定的业务标识关联初选、核对确认及纠正。每个命令另有不可变幂等标识。

- 初选保留本次评分前的调度基准与内容版本，立即计算并保存新日期。
- 核对下一个确认原评分及有效进度。
- 核对记错以本次评分前基准重算 AGAIN，更新日期、清零进度并进入学习；不是先 GOOD 再从 GOOD 后的状态调度一次独立 AGAIN。
- 调度参数重算不代表全量回滚状态，后续学习需求与阶段按当前合法操作更新。
- 审计保留初选与纠正；学科正式复习量及反馈归属以同次最终有效结果计1次。AGAIN 不必等重新学习通过才成为正式失败结果；GOOD/HARD 未核对时不作为已完成复习。
- 同次学习完成、练习尝试和正式复习次数分开；练习成功不增加稳定次数。当前只设计统计口径，不额外增加复杂统计卡片。
- 纠正仅作用于对应知识块、账号、内容版本及当前有效事件链。其他设备已完成更新时拒绝覆盖，重新读取权威状态并提示重新确认。
- 原样重试同一命令返回同一结果，不重复增次数、不重复毕业或回退。客户端超时不作为提交失败的证据。

刷新后没有本轮恢复，但服务端已接收初选的日期保留；未核对 GOOD 不增加进度。新轮按权威状态建立队列，不能推断上轮已经通过。

## 8. 本机切页恢复与同步

### 临时轮次，仅本机当前进程

按 owner/device/session/学科隔离保存组大小、队列、当前卡片、揭晓状态、初选、学习阶段、组末巩固标记和在途命令。

切材料、统计、其他页面或另一学科后返回可恢复。明确结束、删除学科、账号/会话变化、刷新和重启清除；删除或移出当前学科的知识块退出队列。迟到响应不得写入其他账号或轮次。

### 服务端持久业务状态

保存正式事件、下次日期、需学习标记、稳定进度、内容绑定、掌握状态及幂等回执。其他设备可读取这些业务状态并建立自己的临时轮次。临时队列与学习步骤不做跨设备恢复。

仍需联网提交正式操作，未新增离线 Review outbox。存在未知提交结果时本机保留原命令，先确认结果再推进；结束流程也先结算在途请求。

## 9. 学科统计

复用学科统计页面与现有趋势布局，展示服务端已同步数据。

| 区域 | 口径 |
| --- | --- |
| 资料与知识 | 活动 FILE/TEXT/URL 数量、知识块数量 |
| 状态概况 | 待学习（首次或需重新学习）、待复习（已学未掌握）、已掌握；三类互斥并覆盖活动知识块 |
| 学科掌握率 | 已掌握数量 / 活动知识块总量；空学科为0，无数据加载失败另行显示 |
| 单块进度 | 复习卡片显示稳定复习0/3至3/3、下次日期及长期验证等待/通过 |
| 近期趋势 | 沿用当前界面；服务端保留7/30天能力，以本地自然日统计有效完成复习量、不同知识块数及新增知识块 |
| 任务 | 当前各状态数量与现有完成日期指标 |

初选与记错纠正只归属一个最终有效结果；同卡当天多次独立到期复习可有多次正式事件，但不同知识块量按日去重。学习完成与复习完成分别识别，不再通过新协议的单纯 before_state 为空推断全部学习语义。

正式复习结果按初选 reviewedAt 所属的本地日期归属。跨日核对或纠正更新原次结果，不增加纠正日的新复习次数；学习完成按自己的完成日期归属。审计历史仍保留各操作的真实发生时间。

今日到期量是待复习中的日期已到期子集，可用于今日计划计数。未来到期的知识块继续归待复习，保留日期且按时加入自动队列。状态总量校验使用三类之和，今日到期量不再作为另一类相加。

账号、学科、时间范围和时区绑定请求；旧响应不能覆盖新选择。加载失败有明确提示与重试，真实零值和旧数据刷新失败分别呈现。业务操作确认成功或同会话同步完成后刷新相关统计。

## 10. Service、数据与接口边界

当前事实：现有 events 只支持新增不可变评分；改同一 clientEventId 的评分会被拒绝，新ID成为独立事件。现有 ReviewState 没有毕业字段，reps 包含 HARD；dueAt 非空且 PC 校验有限日期。当前三态概况不包含已掌握。新机制需要 PC 和 Service 一起实现。

建议能力边界：

1. Review 状态增加明确掌握状态、稳定进度、需学习标记、内容绑定与最近正式/练习时刻。
2. 持久保存初选/确认/纠正的事件关联和调度基准，独立幂等回执支持原样回放；保留已有不可变历史。
3. 显式支持首次学习完成、重新学习完成及重新开启复习。新操作与普通 GOOD/AGAIN 独立，不通过隐藏评分来表达。

## 13. 研究依据与限制

- [McDaniel、Howard、Einstein（2009）：3R 原研究摘要](https://www.psychologicalscience.org/journals/psychological-science/j.1467-9280.2009.02325.x/)：支持阅读、回忆与核对的学习方法，其大学生材料实验不能直接验证本产品所有知识块及按钮设计。
- [Rawson、Dunlosky（2022）：successive relearning](https://journals.sagepub.com/doi/10.1177/09637214221100484)：支持跨间隔场次的成功提取，并指出足够练习量依材料、学习者、间隔和测试目标变化。
- [Anki 官方统计定义](https://docs.ankiweb.net/manual/stats)：mature 指间隔至少21天的复习类别，不代表停止复习。

本版 GOOD 3天、HARD 1天、AGAIN 10分钟初始分档，后续7/14/30天及连续次数清零属于可调整的产品政策。已掌握表示达到停止自动复习的条件，不承诺永久不遗忘。用户已授权本轮实施；新机制代码、自动验证与真实业务验收分别登记，不沿用旧机制的通过结论。
