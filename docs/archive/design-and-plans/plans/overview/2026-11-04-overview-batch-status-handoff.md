## 问题与目标

每轮 PC 总同步目前枚举全部活动学科并逐个 GET 完整总览。复习成功的 REVIEW_UPDATED 也会安排总同步。没有保存总览的学科按单 GET 契约返回 404，下一轮又重复查询。本次通过一个有界批量状态请求表达缺失，减少 HTTP 请求与 404 噪声；不新增数据库空标记。

## 后端契约

`POST /api/overview-results/subjects/statuses`，使用现有 Bearer access token：

```json
{
  "subjectIds": ["10771b95-b410-4d80-9e62-5272b40b2581", "01a1a110-5278-761a-8c5c-aeec0c40c891"]
}
```

- subjectIds 必填，原始数组长度 1–100，元素均为非空 UUID。超限在去重之前拒绝。
- 相同 ID 按首次出现顺序去重，响应顺序与去重后请求一致。
- 正常结果 HTTP 200，包裹为 `{items:[...]}`。批量读取不写入数据、不生成总览、不发布更新事件。
- 非法输入 400，未登录/会话失效沿用 401；服务或网络异常不得当作空结果。

每项字段为 `subjectId/status/version/outlineVersion/summaryVersion/updatedAt`：

| status | 语义 | 版本与时间 |
| --- | --- | --- |
| AVAILABLE | 本人活动学科，存在通过现行输入/来源有效性检查的完整总览 | 与现有单 GET 相同 |
| MISSING | 本人活动学科，没有当前有效总览；包括无记录、资料变更后失效或结果不完整 | 四项均为 null |
| UNAVAILABLE | 学科不存在、已删除或不属于当前用户，统一返回 | 四项均为 null，不披露结果信息 |

AVAILABLE 的整体 version 可为 0；不能用 `version > 0` 判断是否存在。MISSING 通过状态及 null 元数据表达，不返回正文、目录或摘要。

服务端实际序列化始终包含四个元数据字段；当前 OpenAPI 对 nullable 字段的生成类型可能同时包含 optional。PC 仍应校验实际响应：AVAILABLE 缺少有效版本/时间属于协议错误，不应默认为 MISSING；状态判定不能依赖字段是否省略。

状态有效性复用现有完整结果判断，不能只做表中 exists 检查。该接口只是一次读取时的状态：状态返回后资料或结果仍可能变化，后续详情/写入继续执行原有校验。

## PC 接入位置与顺序

主要位置：`src/api/useOverviewResultsApi.ts`、`src/services/overviewResultsSyncService.ts`、相应 API 类型与测试。保留当前账号/设备/session 票据和迟到结果隔离。

1. `reconcile` 收集本轮 Subject IDs 后，先按原逻辑处理本地待上传/结果未知的 outbox；状态接口不能跳过待保存操作或重写已发载荷。
2. 对需要远端读取的学科去重并分组，每组最多 100 个；空集合不发请求。当前 13 个学科应只发一个状态请求。
3. MISSING：走当前“已确认远端无当前总览”的处理边界，不逐项 GET 完整结果。保留本地编辑与待上传内容，不能清空用户草稿；仍须执行既有本地完整成果的首次上传/seed 判断，不能在看到 MISSING 后直接 continue 跳过首传。
4. AVAILABLE：本地没有已拉取的完整结果，或已知服务端版本/时间变化时，再调用原 GET 拉取完整结果。只有确知本地完整副本对应返回的版本/时间时才可跳过；version=0 不代表缺失。
5. UNAVAILABLE：交给现有核心资源同步核对学科归属/删除状态，不在状态读取回调里直接删除本地资源、草稿或 outbox。
6. 状态请求之后详情 GET 若因并发资料变更返回 404，仍按现行空结果分支收敛；不可无限重试。网络、500、鉴权异常仍保留为对应错误。
7. 状态接口本身 404 表示后端版本/路由需检查，不自动退回逐学科 GET 掩盖接入问题。

状态元数据只用于决定是否读取，不能用来跳过现有 PUT 的版本/输入校验。第一次发布可保留所有待上传 scope 的原 GET/PUT 路径，优先替换没有 outbox 的全量缺失扫描；这是保留写入职责，不是旧协议兼容分支。

## 验收

- 13 个活动但没有保存总览的学科：一个状态 POST，13 个 MISSING，不再发 13 个必然 404 的完整 GET。
- 混合 1 个新版本可用总览与其余空总览：一个状态 POST，仅按需要拉取可用项。
- 相同版本的可用项有完整本地副本时不重复下载；版本 0、资料变化、删除后新建结果等情形不能错误跳过。
- 生成保存成功或其他设备发布总览后，下一次状态检查能发现 AVAILABLE 并拉取；不因之前缺失而永久隐藏。
- 本地待上传内容和失败重试不因 MISSING 被删除/跳过。
- 跨账号、迟到响应、未认证及网络失败不污染当前账号状态。
- 两批以上、重复 ID、空 ID 列表和超 100 条分组正确。
