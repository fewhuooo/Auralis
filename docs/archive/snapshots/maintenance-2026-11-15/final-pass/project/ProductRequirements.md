## 产品目标

Auralis 旨在把学习资料、知识理解、任务执行、复习反馈和多端同步组织成一个连续工作流：

```text
资料或想法进入
→ 归入学科与资产
→ 提炼知识块和任务块
→ 排期、专注与复习
→ 统计反馈
→ 多端同步与继续处理
```

产品不以“页面数量”作为完成标准，而以用户是否能安全、连续地完成上述闭环作为验收依据。

## 目标用户

- 需要同时处理课程资料、知识理解和学习任务的学生。
- 需要在电脑、手机和平板之间切换的多设备用户。
- 希望利用 AI 做资料摄入、问答、提炼、任务抽取和排期建议的学习者。
- 需要离线或弱网下继续记录，并在恢复网络后同步的用户。

## 核心原则

- **学科作为主要上下文**：资料、知识、任务、AI 对话和复习尽量有明确学科归属。
- **块作为核心数据单元**：知识块与任务块可独立创建、更新、同步和关联。
- **本地优先**：客户端可先本地操作，再通过 mutation 和 cursor 增量同步。
- **PC 文件本地优先**：PC Tauri 导入的原始文件先进入当前设备的持久资料库，断网时即可预览和解析，恢复网络后最终同步到 MinIO；同步失败不得撤销本地导入。
- **跨端分工**：不强求三端页面完全相同，而要求核心数据语义一致。
- **AI 可追溯**：AI 结果应保留来源上下文，用户能判断、修改和继续使用。
- **安全隔离**：用户数据、资产、同步记录和长连接必须按用户隔离。

### Overview M4：后台生成与正式采纳（源码、相关验证、唯一审查与隔离浏览器后端接口流程完成；未部署）

PC 对 Source/Subject ALL、OUTLINE 使用显式来源选择和 durable job；候选完成后由用户查看 VERIFIED 预览并主动发布或采纳。正式结果按现行身份/来源校验、版本 CAS 与 receipt 写入，部分 OUTLINE 更新保留已有 summary。离开视图停止观察不等于取消 job；暂停、继续、取消和重连遵循服务端持久状态。FILE/TEXT/URL 的本地编辑沿现有 outbox 同步，并在源 revision 与 owner/device/scope fences 仍成立时提交。隔离浏览器合成 Provider 流程已完成后端接口验证；真实 Provider、native Tauri/SQLite、FILE/OCR、部署与内容质量仍属后续验收。M4 范围关闭不等于 M5/M6 或整体 M1–M6 路线完成。

## 核心场景

### Chat 可视化教学（2026-10-29，计划中）

- 用户围绕资料、选区、大纲节点或自由问题对话；单 Agent Loop 按需检索和读取资料，文字逐字展示，步骤、对比、路线、图表和题卡逐项穿插展示。
- 单/多选和开放问答卡收集答案并自动组装关联原题的消息，由 LLM 反馈和继续；程序不判分。开放问题也可直接在聊天中回答。
- 产品保持轻量：保存对话、组件与作答用于恢复和上下文衔接，不建设学习进度/完成率/掌握度或知识块完成流程，不提供填空题。Overview 与正式学习/复习流程保持现有边界。
- 同会话生成互斥，保留用户草稿；历史题卡可稍后提交。资料权限、幂等、流式异常、取消、恢复与费用分别验收。会话保留和新 Provider 适配是实施前置，尚未交付。完整范围与分阶段验收见[实施计划](../plans/2026-10-29-chat-agent-visual-teaching.md)。
- 新对话默认使用当前学科资料范围；首条消息前可选择文件。首条成功准入后，对话固定 SUBJECT/SELECTED/AUTO 的选择策略与来源/学科 ID，之后重试与活动提交继承此范围；要切换范围应新建对话。每次执行仍按当前权限、READY 和资料版本重新校验。选区引用通过请求顶层 `selectionText` 传递，每轮可单独选择。旧的混合范围对话保留历史查看；若系统不能证明一致范围，不按任意一轮改写绑定，用户需新建对话。

### PC 个人中心

- 左栏「账号与安全凭证」集中个人资料、登录设备管理、退出登录、重置本地离线数据和注销账户。右栏「AI 设置」集中自动生成概览偏好、使用额度和模型服务配置。

### 2026-10-10 AI 完整额度与个人中心（代码与相关自动验证通过；GUI/Provider 待验收）

- 所有生成/embedding 调用受统一任务预算、跨实例并发与持久小时/每日额度保护；服务重启不能重置历史窗口用量，缺失 Provider usage 按保守估算记录。
- 额度入口放在现有个人中心。PC、Mobile、Tablet 展示当前账号本小时/今日额度、已结算用量、在途预留、剩余和重置时间；以 token 为单位，窗口按服务端 UTC，时间在客户端按本地显示。未加载或读取失败时不得显示成实际零额度。
- 账号切换后旧额度不能继续展示或由迟到响应覆盖新账号。额度耗尽或繁忙有明确等待反馈，不自动循环重试；后台摄入延期保留已完成批次，不计作普通失败。
- 本项已由用户明确授权，代码、自动验证与真实 GUI/Provider 验收按 [B 实施计划](../plans/2026-10-10-ai-usage-guard-b.md) 分开记录。

### 场景 1：资料进入知识工作区

用户上传文件或录入内容，将其绑定到学科；系统解析内容并允许用户阅读、提炼、标注、总结或转成知识块。

验收要点：

- 上传对象只能绑定到当前用户。
- 文件状态可查询，失败时有可理解反馈。
- AI 摄入与提炼的来源可追溯。
- 未完成的对象校验不得被写成已安全验收。

### 场景 2：从知识生成行动

用户从资料、AI 输出或手工输入中形成任务，设置学科、时长、负荷、状态和排期，再进入专注流程。

验收要点：

- 任务字段在客户端、API、数据库和同步链路中一致。
- 删除后不会在冷启动或其他端重新出现。
- 排期、专注和完成状态能形成连续操作。

### 场景 3：多端继续工作

用户在一个端产生或修改数据，在其他端恢复同一用户上下文，并正确处理增量、冷启动、断网和冲突。

验收要点：

- 所有同步数据带用户隔离。
- access/refresh token 用途严格区分。
- WebSocket 断连、token 过期和心跳行为可验证。
- 直接 CRUD 与 mutation 删除采用一致语义。

### 场景 4：复习与反馈

用户查看待复习内容、完成专注或任务，并从统计中了解近期投入与完成情况。

验收要点：

- 统计数据来源明确，不把 mock 或本地占位数据当成服务端事实。
- 复习、专注和统计之间的状态转换可追溯。

## 功能范围

### 账号与权限

- 注册、登录、access token、refresh token 刷新。
- 旧明文密码登录后迁移为 BCrypt。
- 普通 API 拒绝 refresh token。
- PC、Mobile 和 WebSocket 使用一致的用户身份语义。

### 学科空间

- 创建和进入学科上下文。
- 在学科内组织文件、知识、任务和 AI 操作。
- PC 与 Tablet 提供适合大屏的工作区，Mobile 提供快速入口。
- PC 学科工作区侧栏提供复习与统计，仍使用 `/subject/:id`；本轮前端交付基础页面框架，后续界面细节由用户调整。

### 学科复习与统计

2026-10-09 用户明确要求完整本地使用，[本地实施计划](../plans/2026-10-09-review-stats-local-first.md)更新此前联网写入范围：

- 两页直接读取本机正式数据，断网可学习、反馈、更新日期和统计，联网后同步；本地未同步知识块同样可学习。
- 正式复习状态、历史、日期及待同步意图跨重启保留。临时轮次仍仅当前进程切页恢复，不恢复到重启或另一设备。
- 延迟上传按真实操作时间排期和归属自然日，不按上传时间重算。多端或正文冲突保留记录并提供明确处理，不静默覆盖。
- 首次导入前业务模型保留云端旧进度未知与历史完整度；最新用户UI移除复习顶部覆盖提示、隐藏统计相关提示，本机数据范围仍不等于完整跨设备历史。网络失败不隐藏已有本地内容；保存到本地失败才阻止当前操作并保留输入。
- 专注仍仅个人页，现行学习分流、间隔和掌握条件保持。

2026-10-08 新机制：用户授权 Antigravity 沿现有颜色令牌统一复习和统计页配色。以下学习机制保持；本地持久与同步边界由上方 2026-10-09 要求更新，实际交付与验证以实施记录为准。

- 知识块为待学习、待复习、已掌握；5 / 10 个不同知识块一组，默认5。待复习含未来与到期，自动今日队列仅取到期；正式服务端提交仍校验同步正文，本地保存允许未同步正文。
- 复习隐藏正文先独立回忆并选择“认识 / 模糊 / 忘记了”，初选立即按GOOD/HARD/AGAIN保存日期。认识与模糊揭晓后仅“下一个 / 记错了”；下一个确认初选，记错关联同次结果从原基准纠正为AGAIN。
- 模糊保留本组末尾一次隐藏回忆，成功保持HARD，失败进入学习；已经纠正或学过的同次AGAIN再次失败可重开学习，不增加第二次正式失败。
- 学习为阅读→隐藏回忆→展开核对，下一个显式保存学习完成，记错回阅读；首次3天，重学10分钟。学习完成与复习初选/核对为不同命令，不能用额外GOOD代替。
- 认识初始3天、模糊1天、忘记/记错10分钟；短期再回忆GOOD后3天且稳定0。合法到期跨天认识核对后7/14/30天，最终至少30天验证并核对通过才毕业。提前/同日/本轮巩固不增加稳定次数，实际练习会更新验证锚点。
- 已掌握退出自动排期，可主动抽查/重新学习；手动失败或正文实质变化解除掌握，标题/来源等元信息编辑保留进度。旧历史和旧端反馈保留，不从旧reps推断新掌握资格。
- 本轮仅本机当前进程保存队列、阶段、巩固标记及原命令，切页面或学科返回继续；明确结束、账号/会话变化、刷新和重启清除。删除或移出的卡片退出该轮，未知结果保留原命令重试，更旧冻结回执不能回退已读取的较新状态。
- 学科统计展示活动资料、KB、任务、互斥三态、实际已掌握/活动KB掌握率和近期学习/复习趋势；Service保留7/30本地自然日能力，PC沿当前7天布局。正式有效复习与不同KB分别计数，确认/纠正归初选日期且同次计1，学习完成独立计数。专注时长与轮次只显示个人页。

### 知识块

- 创建、查询、更新、删除和同步。
- 保存学科、标题、正文、来源、颜色、版本和软删除；知识块不再提供独立摘要或标签字段。卡片短文本从正文临时截取，不成为另一份持久内容。
- 支持块关系和 AI 摄入结果关联。

### 任务块

- 创建、查询、更新、删除和同步。
- 保存名称、描述、学科、时长、负荷、状态、排期、版本和软删除。
- 支持时间线、专注和统计使用。
- 设置截止时间的任务，其新排期必须整个结束于截止时刻或之前；调整时长、截止日期、恢复任务、交换或插入顺延也遵守该约束，任一任务超限时整组拒绝。无截止不限制，历史排期不批量改写，非时间编辑和自动完成保持可用。
- PC 无排期的待办/进行中任务在截止时间到达后自动完成，并保留截止时间；有排期的任务按排期结束时刻完成。已完成或已取消任务不重复写入。应用启动、任务同步刷新及运行中每分钟补处理；应用关闭期间的到期任务在下次启动处理。

### 专注与学习统计

- 按实际专注时间累计，暂停和休息不计入；中途结束也保存已用秒数，自然完成才增加专注轮次。
- 活动计时和最终记录可在当前设备持久恢复；离线最终事件以稳定 ID 重试，服务端同事件只累计一次。
- 个人空间学习时长和专注次数使用服务端专注聚合，不与复习事件耗时重复相加；本设备今日记录按本地日显示。

### 资产与文件

- 获取 MinIO 预签名上传地址。
- 上传后绑定当前用户资产。
- 查询资产和处理状态。
- 解析文件并进入 AI/RAG 流程。
- PC Tauri 支持断网导入原始文件；文件长期保存在当前设备，只有用户删除最后一个引用该 Asset 的 Source 时才删除本地副本，并通过同步把删除传播到其他设备。

### AI / RAG

- 跨功能用量治理（计划中）：平台提供模型执行统一额度与任务预算；用户 BYOK 主要提供计量，不扣平台额度、不套平台任务 token/调用配额。两类保留授权、服务容量、超时/输入资源与有限执行保护；每次实际凭据来源由服务端确定，混合来源分别记账，平台 embedding 仍沿原窗口豁免。全调用实际用量与平台额度分别展示。按[统一方案](../plans/2026-10-16-ai-unified-limits.md)实施，学习只消费策略，尚未实施。
- 普通与流式聊天。
- Chat Agent 可按需搜索和读取会话范围内的资料。首轮可选择当前 Source、手选 Source 或整个 Subject，省略范围时绑定当前用户资料。每次 attempt 捕获范围内的 READY 来源，搜索可进一步缩窄范围。搜索无命中时仍可生成回答，检索或 Embedding 错误须明确反馈。
- PC Tauri 对当前可预览文件执行本地原生提取或 OCR，并向服务端提交统一解析结果；PC Web 不作为发布目标。
- Office 文件即使未在可见预览中打开，也必须可由 PC Tauri 的后台解析任务处理；仅能预览但无法稳定提取或 OCR 的格式不能标记为 AI READY。
- Mobile/Tablet 可以继续上传和查看原文件，但本期不在端侧解析；此类 FILE 在同一用户的 PC Tauri 完成解析前保持等待状态。
- PC 学科工作区新会话默认使用当前学科。用户可在首条消息前选择当前文件或指定文件。首条消息成功准入后，需要开启新会话才能更换资料范围。
- 原生文本选区可用于解释、提问或创建知识块；图片和扫描 PDF 不生成 OCR 文本覆盖层。
- AI 回答只向用户展示来源文件名；保存为知识块前必须允许用户确认并编辑内容。
- PC 文件完成解析并成为 READY 后，自动生成结构化文件大纲与总结；完整成功产物可持久化到服务端供同一用户其他设备读取。生成中间态、失败诊断和未完成分项留在本机；文件大纲在“总览”中直接展开，文件总结复用中间预览区。
- 学科总览只在用户主动点击现有“AI 梳理”入口时生成，输入来自当前学科的本地文件大纲/总结；支持全部、大纲或总结分项重新生成，失败不得删除上一次成功内容。
- 文件 Overview 必须对应当前资料修订；学科 Overview 必须对应当前来源集合及文件结果版本。资料删除或修订变化后，过期结果不得覆盖新结果。
- 手动 Overview 生成须可停止；离开工作区只停止该页面发起的请求，后台自动生成继续。共享生成保留其他消费者的需求；取消保留上次成功内容，不显示为生成失败。服务端总期限须主动终止当前本地 Provider 传输，账号/runtime 或资料修订失效须拒绝旧结果。
- 任务抽取、手写转换和排期建议。
- 使用向量库检索学科或来源上下文。

## 非功能要求

### 安全

- 用户数据必须按认证用户隔离。
- 生产密钥和密码必须通过环境变量或密钥管理注入。
- 上传绑定必须验证对象归属、存在性、大小和类型。
- ParsedDocument 必须同时验证当前 Source revision、原 Asset 内容哈希和用户归属；多设备迟到结果不能覆盖已接受结果。
- 客户端不得覆盖服务端 AI key 或 base URL。

### 可靠性

- 删除语义在 CRUD、mutation 和冷启动中一致。
- 弱网、断线、token 过期和重试有明确反馈。
- 本地数据和远程数据的权威关系明确。
- 数据库变化应有可重复迁移与回滚方案。

### 性能与体验

- 首屏、路由切换和大屏多栏交互避免明显闪烁与阻塞。
- 长文档、PDF、图表和手写画布在目标设备上可操作。
- AI、上传和同步的长耗时操作展示进度与错误。
- Windows MSI 必须离线包含 OCR Sidecar、Runtime、模型和许可证；安装包体积、模型预热、标准页耗时和峰值内存必须先测量并形成回归预算。

### 可维护性

- 模块、API、字段和文档各有唯一权威来源。
- 关键安全、同步和数据路径有自动化测试。
- 构建、部署、备份和恢复有可重复步骤。

## 当前里程碑范围

当前优先级是把账号、资产、知识块、任务块、同步和多端主流程验证闭环，并在 Windows x64 PC Tauri 完成当前文件 AI 辅助阅读闭环，再恢复或扩大增强能力。Tablet 手写代码可以保留，但 Tablet 端 OCR/深度阅读不应先于核心数据安全和同步可靠性进入发布门禁。
