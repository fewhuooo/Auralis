# 学习 Agent 产品与交互设计

更新时间：2026-10-16

文档状态：设计草案，待用户书面审阅确认；尚未实施

权威范围：学习目标、学习会话、教学交互、进度和知识块产出的产品行为与实现边界。本文不确定物理表结构、API 路由或 DTO 签名。

事实来源：现行 [PC 模块](../modules/FrontendPC.md)、[后端模块](../modules/Backend.md)、[API 契约](../contracts/API.md)、[数据库契约](../contracts/Database.md)；当前能力和本设计要求分开标注。

## 目标

让用户围绕一个具体目标，在资料和大纲范围内连续学习。Agent 负责讲解、提问、理解回答、给出反馈并安排下一步；用户能随时调整目标、提问、要求提示或换例子、操作交互演示、暂停，或回到大纲。沿路线学习与自由学习是同一个学习会话的两种入口。

新流程应能恢复用户目标、当前大纲节点、教学对话、互动活动和最近进度，并允许把本节内容整理成可编辑知识块。它复用当前资料检索、AI 调用、知识块保存和正式 Review 服务。学习过程自身不产生正式复习评分、稳定次数或掌握状态。

## 当前能力基线

当前 PC 已有学科总览/文件大纲、资料 READY 门槛、带范围的 Chat 检索、Conversation/Message 对话、知识块编辑保存，以及独立的正式 Review 生命周期。后端 Suggestions 是确定性基线，尚未接入真实 LLM 生成和 Retrieval citations；这些能力并未组成持续的学习编排 Agent。对应现状见 [FrontendPC](../modules/FrontendPC.md)、[Backend](../modules/Backend.md) 与 [Review API](../contracts/API.md)。

当前 `READING_SESSION` 是绑定单一 Source 的阅读聊天，会按现行策略清理 24 小时无活动会话；它不适合作为可长期恢复的课程进度容器。此清理事实仅适用于 READING_SESSION。Chat Message 保存消息正文和状态，但 citation、locator 与原请求中的选中文本不形成可回看的持久证据记录。检索片段没有可信页码或 PPT 页定位，不承诺点击引用可精确跳页。知识块现行正文为 `title/content` 等字段，不恢复已移除的 tags、summary 或 masteryPercent。Review 临时轮次与正式状态/历史分离；临时轮次不是带学会话。现状证据见 [Backend](../modules/Backend.md)、[Database](../contracts/Database.md) 和 [API](../contracts/API.md)。

## 方案取舍

| 方案 | 用户体验与边界 | 取舍 |
| --- | --- | --- |
| 单一学习编排 Agent + 有限应用工具 | 同一 Agent 负责讲解、提问、评估回答和决定下一步；应用在调用前按范围检索，并用受控工具读证据、扩展上下文、保存用户确认后的成果。 | **推荐。** 连续对话自然，状态责任明确；每个学习轮次可用一次 completion 处理反馈和后续教学，无需另起 planner completion。 |
| 固定章节脚本 + 模型填充讲解 | 应用定义课程步序，模型只解释和生成题目；路径可预测，适合固定课程。 | 适合固定内容，但用户插问、改目标和自由学习容易脱离脚本，后续仍需要一套状态协调。 |
| 多个专职教学 Agent 协作 | 讲解、出题、评分、规划由不同 Agent 分工。 | 可分隔职责，但每轮协调与额外调用增加延迟、状态同步和预算压力；目前的目标不需要这些边界。 |

## 用户路径

1. **从总览大纲继续。** 每个大纲节点展示「未开始 / 学习中 / 已学完」、最近学习时间、当前步骤或恢复点、关联知识块。用户选择节点并描述要达成的具体目标；系统创建或继续该节点的学习会话。
2. **自由开始。** 用户在 AI 面板用自然语言提出问题和范围，例如“先离开路线，检索当前学科关于 X 的资料带我理解 Y”。Agent 根据当前学科、用户选择的资料和有效 READY 状态检索。若能对应大纲节点，系统询问是否关联；用户选择前不改变大纲进度。
3. **学习循环。** 一轮可以同时包含简洁讲解、可核对的来源片段、图形或交互活动、一个问题，以及下一步选择。用户回答后，同一会话的下一轮先针对回答反馈，再决定补救讲解、换例子、继续当前目标或询问是否调整路线。
4. **暂停和恢复。** 暂停、离开页面或返回大纲都保留最后一次成功提交的对话、活动状态和恢复点。再次进入时恢复该目标；用户可以从当前步骤继续或主动选择另一个步骤。
5. **完成与知识块。** 用户点“完成本节”表示开始结束流程，不代表浏览或一次答对即自动完成。系统生成知识块草稿，用户可编辑并确认保存；沿用现有 KnowledgeBlock 保存服务。只有知识块保存成功后，才把该节点标成“已学完”、记录最近完成时间和关联块。保存失败时保留对话、完成意图和可编辑草稿，节点继续显示“学习中”，用户可重试或暂停。若块已保存但进度更新失败，重试只补进度关联，不重复创建块。用户取消完成流程时保留会话并回到学习中。

完成判定使用明确的用户动作和持久化结果，不根据浏览时长、选择答案、模型评价或模型的语言判断自动推定。用户可暂不结束，并保留未完成进度。

## 教学轮次与交互内容

每次用户操作都属于一个目标和一个当前步骤。应用提交本轮时，把目标描述、大纲节点及版本、当前和已完成步骤、上一次问题与用户答案、已提交的交互结果、当前资料范围及本轮证据整理为模型上下文。用户提交答案后，下一轮必须带入该答案；模型先反馈回答中正确、遗漏或需澄清之处，再返回下一段讲解/补救或下一问题。

Agent 每轮输出由受控内容块组成：讲解正文、来源证据、图形定义、交互活动、问题/输入定义和可用下一步动作。图形可表达概念关系、步骤流或数据变化；活动类型限制在应用实现并校验的组件白名单，例如单选、多选、排序、配对、滑块和文本回答。活动用声明式数据描述，不执行模型返回的脚本或任意 HTML。图形或活动越界、结构不完整或不支持时，降级为安全图文说明或普通问答，并保留当前步骤。

拖动、排序和滑块在本地即时更新界面；指针释放时保存活动的最新本地状态，不调用模型。仅用户提交或显式要求 Agent 解释当前状态时才发请求；每轮提交的最终值可以带回上下文，不能把每次 pointer move 当成新的模型请求。用户可以在 AI 面板随时改目标、插入追问、要提示、要求换例子、切换演示、跳过当前活动、暂停或返回大纲；路由或请求取消不删除已提交的答案。

### 例子：学习编译原理“遍”

用户从“遍”大纲节点开始，目标是理解遍（pass）及其与多遍编译的关系。Agent 依据用户已展示的定义——“对源语言或等价的中间语言程序从头到尾地扫描并完成规定的任务的过程”——讲解该概念。随后展示一个明确标为教学示例的“源代码 → 前端 → 中间表示 → 后端 → 目标代码”步骤图、可拖动的处理步骤和问题“如果后端需要的信息尚未由前端产生，编译器怎样安排这些工作？”。步骤图、依赖关系与符号信息模拟均为 Agent 的教学示例，不声称来自原文。用户拖动并提交后，应用只提交最终顺序和回答；Agent 在同轮反馈其对依赖关系的理解，再用教学示例解释“多遍”如何让前一遍产出信息供后一遍使用，随后给一个可调滑块模拟“前一遍能否提供符号信息”。用户调整滑块时界面本地更新；提交后 Agent 根据最终值反馈并给出下一步。用户可要求把示例换成自己的资料、追问某个术语或回到大纲。

## Agent 能力与工具边界

学习编排 Agent 仅承担教学对话和选择下一教学动作。应用服务负责会话/步骤状态、访问范围、内容校验、提交幂等、知识块保存和大纲进度更新。Agent 不能直接写 Review 状态、授予掌握、改排期或任务，也不能未经确认保存知识块或更改大纲结构。

学习轮次可调用的能力限于：

- 在本次 owner、subject 和用户明确选择的资料范围内搜索已 READY 材料；
- 对已有命中做一次有界相邻上下文补取，或在当前证据不足且可识别焦点时做一次受应用控制的补查；
- 将返回片段整理为带来源标识的证据，并将当前学习对话/用户答案作为教学上下文；
- 生成白名单图形和活动的声明式定义；
- 提议知识块草稿，等待用户预览、编辑和确认。

搜索、上下文扩展、状态读取和活动运行由本地/应用代码完成，不由模型循环调用工具。每轮在一次 completion 前完成检索和有界补取；不让模型先生成答案再隐式开启多轮规划或额外检索循环。资料范围任务不自动联网。用户明确切换范围时，先展示并确认新的 subject/source 范围。

来源事实和教学解释分开呈现：可回链证据标出来源与片段；模型举例、类比或延伸解释标作解释，不伪装成资料原文。没有命中或材料过期时应明确说明当前资料没有找到支持，并区分一般解释与来源事实。已有检索相似度不是置信度。引用定位仅限可验证的文本片段；没有页码/幻灯片锚点时不呈现精确页码跳转。

所有读取和写入沿用已认证用户及应用服务授权；资料检索需要保持 owner、subject、用户选择的 source、active、generation/revision 与 READY 围栏。资料变更、删除或重摄入使旧证据标记为过期；旧学习记录仍保留当时引用的来源标识、版本和已展示片段作为历史证据，并提示当前来源已变，不能把它当成现行可用资料。新请求不得沿过期证据回答。

## 进度与记录职责

学习进度以大纲节点为入口，节点应有跨排序稳定的身份和内容版本。排序变动保留节点关联；节点文本或目标实质改变时，旧完成状态仍显示其针对旧版本，不能无提示地视为新内容已完成。重新生成大纲时按稳定节点身份/版本匹配；无法确认同一节点时不自动迁移完成状态，给用户选择继续旧记录、关联新节点或从头学习。

设计逻辑上区分以下数据责任，物理表和接口留待实现计划：

- **学习目标**：用户当前希望理解或完成什么、所属学科/所选资料，以及可选的大纲节点身份和版本。自由学习关联大纲必须由用户选择。
- **学习会话**：目标版本、活跃/暂停/完成状态、最近活动、当前步骤和恢复点。学习会话拥有教学步骤和活动进度，不等同于 Chat 历史列表或正式 Review round。
- **教学轮次**：问题/活动定义、用户提交的答案或操作最终值、Agent 反馈，以及恢复该轮所需的证据版本。保存用户实际提交的内容和操作结果；反馈可说明判断依据，不新增独立自评记录。
- **证据引用**：保存当时用于教学的来源标识、Source revision、chunk/片段标识和实际展示的文本摘录；有可信定位元数据时保存该定位，无可信页/slide 信息就只提供片段。来源被软删除、替换或重摄入后，历史记录仍标记为旧证据，实时访问须尊重现有活动与 revision 围栏。
- **知识块草稿与完成结果**：草稿由用户预览/编辑，保存成功后关联新建或用户确认的现有 KB；完成记录引用节点版本和 KB ID。失败的保存意图和草稿可恢复，不自动生成重复 KB。

现有 Conversation/Message 可以提供文本记录，但普通会话的 source 关联和按请求清理行为无法承担长期课程状态；最小可复用做法是沿用消息正文作为学习对话载体，并由持久学习会话状态管理目标、步骤、回答/活动、证据和恢复点。具体是否扩展 Conversation 使用类型或新增与其关联的学习状态模型，属于后续 API/Database 设计；两者必须保持 owner 归属与独立生命周期。

## 版本、幂等与异步安全

每个学习目标/节点、会话和教学轮次都需有稳定标识及递增版本。提交用户答案时绑定当前 session version、step ID、活动定义版本和唯一请求 ID；同一请求重试回放同一结果，不重复记答案、推进步骤或保存知识块。状态更新采用 compare-and-set 式版本检查，冲突时读取最新状态并保留用户未提交草稿。

SSE 响应还需绑定 owner/session/step 代际。用户暂停、换目标、切大纲节点、切账号或 Source revision 变化后，旧响应不能覆盖新会话投影或推进进度。取消停止客户端消费；迟到响应即使已到达，也必须经过服务端当前 session/version/source fence 才可保存。

## 暂停、失败和恢复

- **模型或网络失败**：先持久化已提交的用户答案和活动最终值，再请求模型。生成失败保留待反馈的轮次；用户可显式重试同一轮或暂停，重试不重复追加答案。
- **证据不可用或修订变化**：阻止新回答继续引用旧 generation；保留本轮和用户输入，提示刷新材料或在确认后继续不依赖该资料的一般解释。
- **结构或交互无效**：回退为安全文本问答；不丢弃已提交答案，不自动标完成。
- **保存知识块失败**：保留可编辑草稿、会话和“完成本节”意图，节点仍为学习中；重试沿用同一草稿/保存幂等键。KB 已保存而进度关联失败时，重试只关联已保存 KB。
- **用户暂停或离开**：保存最近成功边界和恢复点；“暂停/返回大纲”结束当前屏幕流程但不完成节点。显式放弃目标需要二次确认，保留已提交历史并将目标标记为已放弃，不删正式 Review 或 KB。
- **配额/预算拒绝**：沿用 Guard/Gateway/账本的真实拒绝和等待信息，暂停当前目标并保留用户输入；不在拒绝后自动循环重试。

## AI 用量原则

当前普通 Chat 每个请求最多 2 次 Provider 调用；检索 embedding 与一次 completion 已占满该上限。现有默认 TopK、400 字符 citation excerpt 和 12000 字符 prompt 上限也继续适用。新流程不能将整门课程描述为一个两调用任务，也不能放大现有限额或上下文边界。未来每个用户教学动作作为独立的有界 AI 任务，经现有 Guard、Gateway 和 reservation/settlement 账本；应用在 completion 前完成当前一轮初始检索和最多一次有界补取，并复用同一 query embedding，不增加额外 completion。反馈、讲解、图形和下一问题由同一 completion 返回。无需 Provider 的状态读取和交互拖动不计作模型轮次。

会话累计调用/token 暴露应从各轮账本投影汇总，让用户可见本次学习消耗；拒绝时按现有 Guard 行为暂停并等待用户显式恢复，不绕过小时/日限制。设计不新增数值限额，也不宣称会降低成本。实际每轮任务键、累计展示字段和拒绝恢复交互在实现前须与现行 AI 用量契约核对。

## 阶段与验收

阶段按可审查的用户价值递进，以下均为拟实施和待验证事项。

| 阶段 | 用户可见结果 | 业务检查重点 |
| --- | --- | --- |
| 1. 目标与恢复 | 大纲节点显示三态、最近学习时间和恢复点；创建目标、暂停、返回和恢复不丢状态。 | 节点重排/编辑/重生成后的身份映射；重复提交；切账号、删除资料和 stale revision 不串写。 |
| 2. 讲解与问答 | 选定资料范围内进行讲解、自由提问、题目/文本回答；提交后带答案继续并先反馈。 | 正确、错误、部分回答；无证据；资料越权/READY/active/revision；模型失败后的同轮重试与迟到 SSE。 |
| 3. 互动与完成 | 白名单图形/活动本地交互；完成流程产生可编辑 KB 草稿，保存成功后更新大纲节点。 | pointer move 不调用 Provider；非法活动安全回退；完成→草稿→确认保存→进度更新顺序；保存失败不丢稿、不重复 KB；旧记录与正式 Review 隔离。 |

验证需分三类，不能互相代替：

1. **业务自动检查**：使用合成 subject/source/outline/KB 内容，覆盖目标调整、自由学习关联需确认、对话/答案/活动恢复、状态版本冲突、幂等重放、来源变更与隔离、配额拒绝、KB 保存失败/进度更新失败、重复完成点击和 Review 状态不变。测试数据不得把真实课件正文或真实模型输出提交入库。
2. **真实模型质量检查**：在授权测试资料上验证模型是否先回应用户答案、证据事实与补充解释是否分明、问题难度/补救是否合适、结构化活动是否可渲染、无证据时是否诚实说明。Provider 调用和业务限额分别记录；合成响应测试不能代表模型质量。
3. **GUI 与业务验收**：人工完成从大纲继续、自由提问并关联节点、交互操作、暂停恢复、目标/示例调整、知识块编辑保存与回到大纲；另验收离线/断线、来源更新、登录切换和额度拒绝场景。服务端健康、类型检查或自动化结果不代表 GUI/真实学习效果验收。

## 后续边界

本设计确认的是用户流程和职责，不是已经存在的产品能力。实现前需要形成独立实施计划，再确定学习会话持久化模型、会话与消息关系、进度 API、活动 DTO、引用快照保留策略、PC 本地恢复及多设备冲突策略，并回写 `API.md`、`Database.md`、`FrontendPC.md`、`Backend.md`、`Status.md` 和 `IssuesAndReview.md`。当前不改变任何接口、数据结构、AI 预算、Review 生命周期或发布状态。
