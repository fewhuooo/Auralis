### 2026-09-27 PC 模态弹窗与浮层设计系统（Modal & Dialog Design System）

1. **禅意与工程化无缝基底（Linear-Style Seamless Canvas & Tokens）**：
   - 彻底消除生硬线条分割：移除 Header 与 Footer 处的 `1px solid` 硬横线切块，全弹窗卡片呈一体化无缝呼吸画布（Header、Body、Footer 依靠精准留白与层级自然过渡）；
   - 遮罩采用 `backdrop-filter: blur(16px) saturate(160%)` 与沉浸微光背景 `rgba(16, 20, 17, 0.45)`；
   - 弹窗卡片采用 16px 精确工程圆角（对齐 Linear / macOS 桌面系统体验）、宣纸温润白底色 `--color-bg-tertiary, #FAF8F5`（深色模式下使用 `#1A1F1B`），边框统一使用极浅发丝线 `rgba(0, 0, 0, 0.08)`（深色 `rgba(255, 255, 255, 0.08)`）；
   - 阴影体系：采用低反差平滑双层环境漫反射阴影 `0 24px 64px -12px rgba(16, 22, 17, 0.18), 0 8px 24px -4px rgba(16, 22, 17, 0.08)`，消除顶部生硬发光条，质感通透纯粹；
   - 关闭按钮：采用 28px × 28px 极简微圆角（6px）幽灵按钮，hover 平滑半透明微背景，消除浮夸旋转；
2. **三层结构与尺寸档位层次（3-Tier Layout & Size Hierarchy）**：
   - 无缝三层布局：顶部常驻吸顶标题区（`.modal-shell-header`，padding: 24px 28px 8px 28px）、中间独立纵向平滑滚动内容区（`.modal-shell-body`，padding: 8px 28px 18px 28px，5px 定制轻薄圆角滚动条）、底部吸底停靠操作区（`.modal-shell-footer`，padding: 8px 28px 24px 28px）；
   - 提供五档标准化尺寸宽度：`sm` (420px)、`md` (520px)、`lg` (680px)、`xl` (840px)、`auto`；
   - 彻底消除弹窗内部卡片（如知识块详情、确认框）的二级框中框嵌套边框，内容直接在卡片画布上舒展呈现；
3. **现代工程化 8px 控件系统与微排版（Engineered 8px Controls & Typography）**：
   - 告别卡通感药丸圆角，全面推行 8px 精确圆角矩形控件：
     - **主按钮（Primary）**：哑光纯粹 Zen Sage 绿 `#5B6C47`，8px 圆角，高度 36px，内嵌顶边发丝微光，文字 13px weight 500；hover 加深为 `#4F5E3C`，active 触发 `scale(0.985)` 微触觉反馈；
     - **次按钮（Secondary）**：现代极简扁平幽灵灰 `rgba(0, 0, 0, 0.035)`，微边框 `rgba(0, 0, 0, 0.08)`，文字沉稳深灰 `#3F4A41`；
     - **危险按钮（Danger）**：纯正克制陶土绯红 `#D93838`；
   - 标题与文本微排版：标题采用 16px、font-weight 600、负字间距 `letter-spacing: -0.015em`；说明文案收敛为 13.5px、行高 1.62、次要灰度 `#4B564D`；
   - 标签与芯片：学科选择与预设提示词芯片全面收敛为 6px 圆角幽灵微胶囊，消除沉重黑边框；输入框采用 8px 圆角与柔和鼠尾草聚焦环。

### 2026-09-26 PC AI 参考范围与状态反馈

- 学科工作区打开文件后，默认参考当前文件；用户显式选择其他文件时，将当前文件与所选文件作为可见、可移除的参考集合，最多 100 份。全学科范围须用户显式选择，未选择参考资料时保持普通聊天。界面所示范围须与实际请求和检索范围一致。
- 文件预览的显示名称变化只更新文字，不触发内容读取；Source、Asset、MIME 或扩展名等内容身份变化应重新加载。通用服务不可达时，侧栏状态应反映网络/服务错误；取消请求不显示离线，较旧响应不得覆盖较新的连接判断。
- 个人空间的导出说明列明实际包含的数据；登录密码说明为单向哈希保存；AI 数据处理说明准确表示请求经服务端转发。

### 2026-09-25 个人空间 AI 模型设置交互

用户填写聊天 Provider、Base URL、聊天模型和 API Key。通用兼容服务须明确填写 Base URL 与聊天模型；切换服务商时清除旧模型，避免误用上一服务商的标识。模型列表检测为可选辅助；保存配置后可检测候选模型，手动填写模型可直接测试连接，反馈显示服务端实际测试的聊天模型。Embedding 由服务端维护，不在个人空间展示配置项。

### 2026-09-26 注销账户密码确认交互

注销 API 返回 202 后清除本地会话并跳转登录页。确认密码不匹配返回 `UNAUTHENTICATED` 与 `Invalid credentials` 时留在个人空间并显示接口错误；Bearer token 无效返回 `Authentication is required` 时仍执行全局 access token 刷新与重新认证流程。

### 2026-09-24 紧邻任务顶部交换

两项任务原排期首尾紧邻时，拖到顶部交互栏会交换两项先后顺序，且仍共同占用原时间窗口。例如 09:00–10:00 与 10:00–11:30 交换为 09:00–10:30 与 10:30–11:30。前端显示服务端实际返回的开始时间；校验失败时保留原排期。

### 2026-09-24 Timeline 卡片主体落点

卡片主体拖放把被拖任务接到目标任务结束后的首个半小时槽；目标及其他任务保持原位，完整时长与后续排期冲突时直接拒绝并保留原排期。主体提示显示接入时间和冲突拒绝。普通空白槽位仍按原有插入顺延处理；只有卡片最顶部 `.task-header` 执行双任务交换。

## 设计目标

三端共享“极简禅意（Zen Minimalist）”语言，同时根据设备职责采用不同信息密度：

| 端 | 主要场景 | 设计重点 |
| --- | --- | --- |
| PC | 桌面学习工作台、学科与资产编排、时间线 | 高信息密度、多栏、鼠标键盘、文件预览、拖拽 |
| Mobile | 快速捕获、专注、复习、随身 AI、统计 | 单手操作、短路径、底部导航、弱网反馈 |
| Tablet | 横屏学习、文件阅读、工作区、手写与伴读 | 左侧导航、多栏全景、触控、手写、面板联动 |

设计文档定义目标行为，不负责维护构建或验收状态；状态见 [当前状态](../current/Status.md)。

### 表面与圆角

- 页面背景使用禅白或暖灰白，不使用纯白大面积强对比。
- 主卡片采用 `16px` 左右圆角、发丝边框和极轻阴影。
- 模态弹窗（Modal / Dialog）采用温润大圆角 `24px`（`--radius-xl`）卡片与无缝一体化设计，彻底取消头部与底部的 1px 硬线条分割，依靠充裕留白划分层级；宽度体系遵循更透气的梯度（`sm: 480px`, `md: 580px`, `lg: 760px`, `xl: 920px`）；内边距统一放宽为头部 `30px 36px 14px`、内容区 `14px 36px 24px`、底部 `16px 36px 32px`。
- 模态弹窗配色全面对齐全站极简禅意系统：浅色底板采用宣纸暖米白 `var(--color-bg-tertiary, #FAF7F2)` 搭配浅发丝边框 `var(--border-default, #DDD5C7)` 与暖炭黑毛玻璃遮罩（`rgba(28, 28, 26, 0.42)`）；深色模式严格对齐暖炭高阶底板 `var(--color-bg-elevated, #3d3b38)`，杜绝绿黑杂色；弹窗内表单输入框、单选芯片、拖拽区与嵌套卡片底色采用燕麦米白 `var(--color-bg-primary, #F7F2EB)`，形成与宣纸弹窗卡片温润分层的宣纸/燕麦纸层次，聚焦态切换为纯白高亮。
- 模态操作按钮统一采用全圆角 Zen 胶囊（`border-radius: 9999px`，高度 40px，主操作为统一的 `Primary Gradient` 禅绿渐变 `linear-gradient(135deg, #9EAD80 0%, #8B9A6E 100%)`，次操作为燕麦米白底板配发丝边框，危险操作为陶土红温润渐变）；关闭按钮统一为 `32px` 纯圆透明无边框交互靶点；表单输入控件统一采用 `14px` 舒适圆角。
- 胶囊按钮和筛选器可使用全圆角，但长正文容器不得滥用胶囊形态。
- 侧栏、搜索、弹层可使用 `backdrop-filter: blur(20px)`，必须提供不支持毛玻璃时的实色后备。
- 阴影透明度控制在 `0.02–0.06`，禁止厚重悬浮阴影。首页三栏等大容器采用分层微阴影增强底部立体沉降感（如 `0 10px 24px -4px rgba(0,0,0,0.05), 0 2px 6px -1px rgba(0,0,0,0.03)`）。学科空间卡片、学科中心知识块及搜索输入框统一采用分层立体底部阴影，悬浮态轻柔抬升并温润扩散微投影，保持容器顶部预留缓冲空间（`padding-top: 8px`），避免悬浮上移被顶栏裁切。

### 排版

- PC 普通 UI 文本统一使用 `var(--font-family-base)`（DM Sans 优先，系统无衬线回退），页面组件不得再声明独立的 Inter、Outfit、Plus Jakarta Sans 等字体。
- 代码、知识图谱节点等确需等宽的内容统一使用 `var(--font-family-mono)`（Fira Code 优先，系统等宽字体回退）。
- PC 根字号固定为 `16px`；语义字号使用 `caption`（12px）、`body-sm`（13px）、`label`（14px）、`body`（16px）、`body-lg`（18px）、`title-sm`（20px）、`title`（24px）和 `title-lg`（30px），番茄钟等大数字使用 `display-sm`（48px）或 `display`（72px）。
- 标题字重 `700–800`，字距轻微收紧。
- 正文行高 `1.5–1.7`；手机正文不得因追求精致而低于可读尺寸。
- 次要信息只能降低对比，不能依靠过小字号隐藏。

| 多栏展开、折叠和联动 | `400ms` | `cubic-bezier(0.16, 1, 0.3, 1)` |
| 页面进入 | `200ms` | `ease` + opacity/translateY |

- 动效必须表达状态变化，禁止为装饰阻塞首次操作。
- 路由切换与导航指示器时序必须避免“先回旧位置再跳新位置”。
- 尊重系统减少动态效果设置。

### 深色模式

- PC 以 `html.dark` 为入口，背景使用暖炭色 `#1F1E1C`、`#292825`、`#33312E`，文字使用浅燕麦色。
- Mobile / Tablet 当前以浅色为主；在完整定义令牌、图表、图片和手写画布之前，不宣称深色模式支持。

## 通用交互状态

每个数据页面必须设计：

- 首次加载骨架或进度，不出现无解释空白。
- 空状态说明“为什么为空”和下一步操作。
- 请求失败展示用户可理解的原因、重试和安全退路。
- 保存中、已保存、同步中、离线、冲突和失败状态可区分。
- 删除等危险操作明确影响和可恢复性。
- AI 长任务展示输入上下文、处理状态、失败和重新执行入口。

## 导航与跨端原则

- 同一端内部导航稳定，禁止因窗口尺寸变化在 Mobile 与 Tablet 路由间自动反复跳转。
- `pages/launch/index` 只负责首次设备分流；进入某一端后保持该端导航体系。
- 微信小程序固定进入手机体验，不注册 Tablet 页面。
- 登录失效回到当前端登录页：手机 `/pages/mobile/login/index`，平板 `/pages/tablet/login/index`。
- PC `/login` 使用独立公共布局，不显示认证侧栏/头部；受保护路由仅在完整 user+token 会话下显示认证壳，未登录或会话不完整时返回 `/login`，避免认证初始化请求异常造成白屏。

### PC 全局框架

- 左侧毛玻璃主导航保持窄栏，当前选中项必须同时用位置、形状或文本表达，不能只靠颜色。
- 全局搜索可使用 `Ctrl+K`，必须提供可点击入口与键盘焦点管理。
- 主内容采用响应式卡片网格；低宽度下优先保证主任务，不强行保留所有并列栏。
- Tooltip、菜单和弹窗必须脱离可能裁切的 transform/overflow 容器。
- **图标系统**：PC 端所有界面功能与语义图标统一采用 `@tabler/icons-vue`，线条粗细使用 `stroke-width`（发丝线条 1.5 ~ 2 之间），遵循极简克制的 Zen 设计语言；禁止使用杂乱风格内联 `<svg>` 或混入其他第三方图标库（如 `lucide-vue-next` / `@element-plus/icons-vue`）。番茄钟进度圆环、Brand Logo、AI 伴读四芒星渐变粒子等专属图形渲染属于图形可视化，维持原生矢量实现。

### Dashboard

- 首页看盘右侧采用上下双卡片分区布局：上半部分为「日程任务」（纯线性任务列表），下半部分为「待办清单」。日程复选框根据任务完成状态呈现；排期任务结束后发生 TASK 投影刷新时，自动完成检查应立即重试。
- 上半部日程任务：移除 06:00~23:30 垂直网格槽位与当前时间指示线，不作为可拖拽调时，按开始时间升序简单排列展示；支持点击复选框即时切换完成状态，已结束且已完成的排期任务不可取消完成并显示原因；支持移出未完成日程。周视图保持 7 天各日任务横向概览与点击快速切换。
- 时间轴数据窗口固定为当前/所选日期所在的完整自然周（周日至周六）；首页和独立时间轴使用同一窗口。首页日期格在日数字上方显示 `Sun` 至 `Sat` 英文星期缩写，7 个日期均匀分布，未选中态无边框，选中态使用固定约 `36px × 36px` 的圆形绿色背景；顶栏以“时间轴 · X月”提供月份坐标与日/周视图胶囊切换及新建任务按钮。
- 下半部待办清单：使用独立圆润条目，移除拖拽手柄与拖动属性，纯列表展示未排期任务；标题行最右侧增加「前往排期」微胶囊按钮（带右箭头图标），方便一键跳转至排期副驾；条目右侧或信息区展示截止日期（DDL）徽章，截止日期逾期时高亮低饱和暖红警示，无截止日期的活跃任务也可正常展示并排期；窄宽布局下标题优先保留可见空间，学科徽标允许收缩并以省略号截断，不能挤掉任务名称；点击复选框直接完成。
- 复杂拖拽编排、全天半小时网格与换位操作完全收敛在 `/timeline`（排期副驾）页面，保持首页看盘的轻量与高效。

### SubjectHall

- 学科卡片展示名称、进度或掌握度和明确进入入口；注册后没有学科时展示真实空状态，不注入“未分类”占位卡片。
- 创建与编辑采用统一弹层，不让卡片网格在操作时重排。
- 编辑已有学科时保留服务端版本并提交 `baseVersion`，名称、描述和图标修改成功后关闭弹层并更新卡片状态。
- 学科卡片删除沿用统一确认和软删除反馈，历史遗留默认标记不改变删除能力。
- 搜索、空状态和大量学科时的滚动行为可预测。

### SubjectWorkspace

- 目标是“选择资料或知识 → 在主区阅读/编辑 → 在辅助栏查看关系、总结或任务”。
- 知识块的“来源”必须显示关联 Source 的可读 `title`（对文件资料即原文件名），知识块学科标签必须显示关联 Subject 的可读 `name`；不得把 `sourceId`/`subjectId`/UUID 当成名称展示，关联投影暂缺时分别显示中性占位。ID 仅用于筛选、关联和写回。
- 学科图标需在大厅、工作区、首页、时间线和全局功能侧栏保持一致；新建学科使用语义键对应的线条图标，已有 Emoji 原样显示，空值或未知语义键使用统一书本线条图标回退。Subject 不提供独立颜色；创建时不提供主题色选择，所有学科卡片、图标、选择态以及由学科触发的新知识块/任务统一使用 Sage Green `#7D9372`。Task 不读取持久化颜色字段，KnowledgeBlock 的独立 `colorOverride` 保留。
- 多栏应允许聚焦主内容；辅助栏关闭后释放空间，而不是留下空白占位。
- 文件预览统一由 `FilePreview` 承载加载、失败、下载和不支持状态；当前 PC 先用自托管 File Viewer 覆盖 PDF、DOC/DOCX、PPT/PPTX、图片和文本，Excel/未知格式在上传前拦截。上传入口与解析器能力保持一致，仅接受 PDF、DOC、DOCX、PPT、PPTX；图片和文本仍可预览但不允许创建 upload intent，`canPreviewFile()` 不再依赖 `allowedForUpload`，并以可操作的支持格式提示反馈。预览保持一个统一面板：学科页现有文件名顶栏承载缩放与旋转控制，缩放按 `− / 倍率 / ＋` 排列并与重置按钮放在同款圆角组内，旋转按线条图标、角度、线条图标放在另一组同款圆角框内；页码/总页数和前后页导航在预览主体底部占用独立布局空间。上下栏以轻微投影与实体按钮建立层次，中间文档上下保留约 12–16px 安全留白；搜索、打印、下载、HTML 导出和主题切换不进入预览工具栏。学科文件列表行不显示装饰性文件类型图案，文件名从行内容区起始。宿主不叠加会遮白正文的渲染遮罩，File Viewer 自身负责内部加载状态；首次宽度适配只执行到用户第一次交互，避免缩放后被重新 fit 回原倍率。控制按钮不因 renderer 加载状态被禁用，动作仅在组件 ref 尚未建立时暂存，不以 `load-complete` 作为执行硬门禁；基础 `@file-viewer/vue3` 组件通过 `withFullViewerOptions` 使用 full preset，缩放调用公开的 `zoomIn`/`zoomOut`/`resetZoom`，PDF/图片旋转通过 `applyViewState` 执行，避免 full 包装组件运行时 ref 丢失方法；旧的图片内部旋转栏隐藏，不支持 renderer 视图旋转的 Office 类型才回退到外层旋转。每次签名 URL 下载只允许最新文件选择提交结果，较早的响应不替换当前 renderer 输入。倍率和旋转角度由 renderer 实际状态回传。真实 DOC/DOCX 排版或资源兼容性不足时，替换组件内部 renderer 为服务端转 PDF，不改变学科工作区交互契约。
- SubjectWorkspace 文件栏只展示真实 Source 文件，不生成或显示独立的 `· 总结.md` 虚拟文件。选中文件后直接显示 `FilePreview`；总览中的“总结”快捷入口在同一中栏显示本地 AI 总结，并可返回文件，不增加右侧总结栏。文件行的删除操作默认悬停显示、键盘 focus-visible 时保持可见，并在确认后执行 Source 软删除；本地仍有 `SOURCE/CREATE` outbox 时排队有序删除，不直接请求尚未存在的远端 Source。墓碑和 DELETE outbox 成功写入后，当前文件列表、计数、AI 总览派生缓存和 Profile 中该文件的本地解析进度必须立刻消失；OCR/parser 取消、任务状态和加密 cache 清理在后台执行，不能拖慢界面或选中项回退。取消、未登录、版本冲突、资源不存在和服务端失败都必须有明确反馈。
- 知识图谱是关系探索辅助，不能成为访问知识块的唯一方式。
- AI 提炼必须显示当前学科和来源文件上下文。
- PC Tauri 学科工作区只为当前打开的 Source 创建临时 `READING_SESSION`，切换或离开时 best-effort 删除，不回跳或恢复历史；AI 请求通过 `readingContext` 先检索当前文件，只有确定性识别到跨文件意图时才扩大到同学科。文件未解析完成时发送入口弹出提示并导航个人中心查看进度。文件行仅显示无文字状态点，解析完成后消失，详细阶段、失败、重试和取消集中在 Profile 的文档解析中心；本地 upload complete 后仍须显示服务端 `VALIDATING/PARSING/INDEXING`，并且只有服务器 Source 变为 `READY` 后才能提问。Profile 对无本地 job 的 `AWAITING_CLIENT` 文件提供“开始本机处理”；该操作先同步并确认 Source 已在服务端建立，未确认时显示本地同步状态而不发起解析。单个历史文件失败不得阻断后续文件恢复。未挂载桌面 runner 时中心必须显示不可用原因，不能显示为无任务。可见 File Viewer 与离线 PDF/OCR 适配器必须解析同一精确 PDF.js 版本，避免共享 WebView worker 的 API 版本混用。预览中的原生选中文本可解释、追问或在确认标题/正文/标签后保存为当前学科/文件知识块。
- 登记本地参考文件弹层必须明确显示选择文件、名称和归档学科三个前置条件；确认按钮在缺少任一条件或上传中禁用。上传中显示当前阶段和百分比，上传/登记失败以可理解通知反馈且保留弹层，允许用户修正后重试；直传完成后先把 Source 保存到本地、关闭弹层并立即刷新本地资料列表，后续同步不阻塞当前操作。浏览器直传使用服务端返回的可达预签名地址，不把容器内部 hostname 暴露给用户。

### Asset 与 Timeline

- Asset 明确区分待上传、上传中、处理中、完成和失败。资产树首屏优先展示本地 Subject、Source、KnowledgeBlock 与 Task 投影；单项本地读取或云端刷新失败时保留可用的本地树并结束 loading，不以永久转圈代替降级。云端数据由各 Store 写回本地后，资产树自动重建而不重新显示 loading。真实 Source 文件预览统一由 `FilePreview` 的 bare 模式承载，资产树将 Source `id`、`assetId`、`name` 与 `fileType` 传入该组件；首页不再提供冗余 PDF 伴读入口。
- Asset 关系星图以真实 Subject、Source、KnowledgeBlock 关系为依据，画布使用 Sage 绿学科节点、蓝灰文件节点与宣纸底色。关系使用对称节点互斥、按边类型设目标长度的弹簧吸引、弱重力与速度阻尼，初始坐标由稳定 ID 决定，初始模拟在收敛或 180 帧上限后停止。同范围刷新保留现存节点坐标与镜头，切换全局/学科范围时重新适配。Source 连接所属 Subject；KnowledgeBlock 的 `sourceFileId` 指向同学科现存 Source 时连接该文件，否则连接所属 Subject。鼠标、触控与触控笔均可拖动画布平移或拖动任意节点；节点拖动期间被拖节点保持在指针位置，关联邻居实时响应弹簧力，每段响应最多 36 帧并在收敛时提前停止；释放后最多 30 帧低强度松弛，使图谱轻微回弹并稳定。拖动/取消手势不触发节点选择，点击文件节点后在中栏打开该 Source 的 `FilePreview`，点击知识块节点后在中栏打开对应知识块编辑器；Home 继续触发 `open-block-detail`。图谱是关系探索辅助，知识块仍可从资产树直接访问。
- 资产库的“全部任务”与学科任务目录展示当前用户的真实 Task Store 数据，不显示固定演示任务；任务按 `未排期`、`未完成`、`已完成` 并列分组，已完成判断优先于未排期判断，组内按截止时间排布。任务编辑使用 30 分钟步进的预计用时选择，不再显示认知负荷按钮，并通过显式保存写回任务详情。时间轴导入入口通过 `/asset?focus=unassigned-tasks` 聚焦未排期任务。
- Timeline 拖拽必须有落点反馈、冲突提示和键盘/表单替代操作；原生拖拽状态必须含任务 ID，已排期任务还必须含原槽位。日视图固定呈现 08:00–22:30 的所有 30 个半小时刻度行，刻度行高度固定（80px+4px gap），不随任务存在而被压缩或隐藏；任务卡片按时长跨越网格，通过绝对定位层在视觉上向下跨越对应数量的半小时槽位，左侧时间标尺所有半小时刻度完整可见。普通空白时间槽执行原有插入顺延；任务卡片主体将被拖任务接到目标结束后的首个半小时槽，若与后续任务冲突则拒绝，其他任务保持原位。失败时保留完整原排期。仅卡片最顶部文字标题栏（`.task-header`，收敛为 `fit-content` 且文字子节点设为 `pointer-events: none` 阻断误清除）是双任务交换落点，并通过独立 drop 阻止事件冒泡；离开顶部文字区域的卡片主体及空白处均作为插入落点，不触发交换；待排期任务拖到该栏时给出可理解错误。拖回待办仅以任务 ID 取消排期。
- 插入请求包含源任务版本与 Timeline 当天 08:00–22:30 的时间窗口；服务端在单事务内验证版本、完成/取消状态、窗口边界与最终区间冲突，并返回实际变化的 Task。客户端拒绝覆盖源任务或受影响日上已有 pending/conflict/error 的本地同步状态；成功后安全写入本地 Repository、更新内存投影并触发 read sync，失败不改本地投影。
- 卡片主体的已排期任务移动走严格放置，普通时间槽仍走插入顺延，两者均不调用 `schedule-swaps`；`.task-header` 的已排期任务交换继续调用服务端原子交换。排期移入过去时段、顺延越过当天窗口、或需要移动已完成固定任务时必须拒绝并保留原状态。
- Timeline 与 Dashboard 首屏优先呈现当前用户/`serverDeviceId` 范围内的本地任务投影，远端刷新不得阻塞已有任务显示；读取或刷新失败时保留已显示数据。日期切换只更新内存中的选中日并重建槽位，不能以重读本地库为代价清空时间轴。
- 单任务拖放、按天排期和拖回待办只等待本地 repository/outbox 写入并立即重建内存槽位，云端 push/pull 在后台执行；云端失败保留已保存的本地结果，本地写入失败以通知反馈。双任务换位的持久化原子组尚未接入现有 outbox，继续作为 P1 风险，不得误记为已满足服务端原子交换验收。
- 所有 PC 排期写入按半开区间 `[scheduledAt, scheduledAt + durationMinutes)` 检查冲突；任务可在前一任务结束的同一时刻开始。取消任务不占用区间，已完成但保留排期的任务继续占用区间。按天排期寻找无冲突槽位；头部双任务换位必须在提交前同时验证双方新区间与其它排期及彼此不重叠。
- 排期修改与任务状态修改不得产生互相覆盖的无提示保存；完成任务不自动清除排期，移出排期必须是显式操作。Store 在启动和每分钟检查到期状态：有 `scheduledAt` 的任务在 `scheduledAt + durationMinutes` 结束时刻到达后自动完成并保留排期；无 `scheduledAt` 的任务不再因 `dueAt` 到期而抹除截止时间，用户设置的 `dueAt` 永久保留；Timeline 待安排卡片与待办列表均显示 DDL 提醒徽章，逾期时高亮警示。所有无排期的未完成活跃任务均可进入待安排队列并支持拖拽排期。拖放、按天排期与换位必须在目标 `scheduledAt` 早于当前时刻时拒绝，保留原位置且不发 API 或离线 mutation，并通过既有错误反馈显示原因。

### Pomodoro

- PC 专注页使用宽屏双栏结构：左侧为计时核心与环形进度，右侧为当前任务选择和今日数据。
- 开始、暂停、重置、专注完成和休息阶段必须有明确的文字或状态反馈；任务选择使用可读的胶囊式控件。
- 计时完成后更新任务 Store 的专注统计；浏览器/Tauri 的后台、刷新和长时间计时行为仍需人工验收。

### Profile

- 账号信息、外观和偏好分组，危险操作单独区域。
- 主题、字体等设置即时预览并可恢复默认。
- 账号区同时展示当前 user/device/session 状态；登录会话列表支持查看当前设备并撤销其它会话，加载失败必须有明确状态。
- 个人空间提供“退出登录”按钮；确认后清理当前本地会话并跳转登录页，服务端 logout 异常需要以通知反馈，不能阻断本地退出。

## 页面级验收清单

每个页面至少检查：

1. 路由入口与返回路径正确。
2. 未登录、token 过期和退出行为符合当前端。
3. loading、empty、error、offline、saving、synced 状态可识别。
4. 主要任务不需要依赖归档中的旧入口。
5. 小屏、常规宽度和目标大屏下无关键内容裁切。
6. 键盘、鼠标、触控和系统安全区符合目标平台。
7. 动效不造成首次点击闪回、白屏或布局跳动。
8. 数据来源、用户归属和同步状态清楚。
9. AI 输出、上传与解析失败可重试。
10. 构建通过与人工交互验收分别记录。

## PC 文档处理与 OCR 诊断

- 文档处理按真实页码推进：每页 OCR 前写入 `OCR_RUNNING` 检查点，页结果保留 `pageNumber/totalPages`、图片字节数、行数和耗时；空页不终止后续页，下一页继续处理并按有序 block ordinal 输出。
- 如果整份文档所有页归一化后都没有文字，任务以稳定错误码 `OCR_DOCUMENT_EMPTY` 失败；UI 展示页级进度和“未识别到文字”的可行动提示，不把空页误报为成功，也不伪造页数。
- 诊断是有界、可复制的 allowlist 摘要：仅含页码、总页数、图片大小、行数、耗时、结果和安全错误代码/说明。复制到剪贴板的文本不得包含 OCR 正文、完整图片路径、`Authorization`、签名 URL 或未 allowlist 的原始字段；复制失败须保留可见诊断而不阻塞任务。
- OCR 诊断只在本机处理边界可见，正文经现有加密 cache/package 边界上传；Rust/sidecar 日志同样只记录受限统计和截断 stderr，不记录识别文本或密钥。
- 断网暂停后点击继续时，带 payload receipt 的任务经 `PAUSED_NETWORK -> QUEUED -> UPLOADING` 直接恢复上传，不重跑 OCR、download 或 hash；无 receipt 的 `QUEUED` 任务仍回到解析流程。`NETWORK_OFFLINE` 对外保持稳定错误码，详情只显示 allowlist reason。
