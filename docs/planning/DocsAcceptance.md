# 文档与验收计划

更新时间：2026-10-28

文档状态：现行计划

权威范围：文档真实性、链接、Agent 可执行性、构建证据和人工验收记录

事实来源：文档架构设计、实施计划、当前状态与 Agent 协议

## 目标

确保文档能作为开发者和 Agent 的可靠维护接口，而不是过期说明的集合。

## 当前事实

- 分类文档体系与 2026-07-10 日期快照已建立，`docs/README.md` 是唯一现行入口。
- 2026-07-10 的文档重构执行计划已移入[维护历史](../archive/maintenance/2026-07-10-documentation-reorganization.md)，其中任务号和命令仅用于追溯。
- 当前实现、验证证据与未关闭风险分别由 `modules/`、`current/Status.md` 和 `current/IssuesAndReview.md` 维护；本页只维护后续文档验收方法。

## 维护检查

1. 整理文档时保护工作树中的已有修改，归档正文保留历史原貌。
2. 新增或移动现行文档时，确认元数据、唯一职责和入口登记。
3. 检查受影响文档的相对链接、旧路径和文件路径。
4. 修改实现说明时，只核对本次涉及的路由、Controller、Entity、配置或 Compose。
5. 按[编码前协议的验证节奏](../agent/BeforeCoding.md#验证节奏)选择检查；纯文档整理检查登记与链接，不运行应用测试或构建。
6. 记录 GUI、真机、外部服务未验收边界。
7. 每次代码改变按 Agent 回写矩阵更新。

## 验证

- 受影响文档的失效相对链接为 0，现行文档能从文档中心到达。
- `docs/` 根目录只剩 `README.md`。
- 现行文档不再引用旧现行路径。
- 文档范围 `git diff --check` 无新空白错误。
- 涉及实现的任务记录实际执行的构建/测试命令与退出结果；按范围不需要的检查说明原因。

## 完成定义

- 当前 Agent 能只从 `docs/README.md` 找到必读和回写文档。
- 归档不被误作现状依据。
- 当前事实、未来计划、历史记录和展示材料互不重复冲突。
