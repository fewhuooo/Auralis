## 当前工作入口

近期工作由开放问题驱动，不把早期重写或迁移清单重新当成未实现功能。PC 登录守卫、后端测试、现行同步和 ticket 实时协议已有实现；后续核对实际行为、跨端差异和验收证据。

| 顺序 | 工作范围 | 进入条件与完成边界 |
| --- | --- | --- |
| 1 | 已知 correctness 与类型/测试门禁问题 | 按问题登记的证据和关闭条件处理知识块会话发布、学科后台作业输入、Mobile Review 漂移及候选门禁失败；先复核当前源码 |
| 2 | 身份、资料与数据恢复 | 验证注册/重置/会话撤销、账号隔离、上传解析、删除、冲突、离线队列与恢复；保留失败证据 |
| 3 | PC 与跨端主流程 | Tauri、H5、微信、Tablet 分端验收，再验证双设备同步、排期、复习与 Chat 恢复 |
| 4 | AI 与外部依赖质量 | 验证现行 Markdown Overview、Chat 原生工具、检索与来源、真实 Provider 异常和用量；自动测试不替代质量样例 |
| 5 | 候选发布 | 按[部署测试前门禁](PreDeploymentReadinessTasks.md)收口配置、制品、安全、监控、备份恢复和回滚 |
| 6 | 后续能力 | 手写和其他平台按已确认产品范围独立排期，不能擅自扩大当前发布范围 |

## 优先级

| 优先级 | 目标 | 证据要求 |
| --- | --- | --- |
| P0 | 防止数据泄露、不可逆损失和生产凭据泄漏 | 用户隔离、安全检查及可恢复证据 |
| P1 | 可靠主流程与外部服务闭环 | 对应自动验证及真实环境验收 |
| P2 | 发布和体验完善 | 构建、GUI、真机、监控和发布演练 |
| P3 | 增强能力 | 核心门禁完成后的专项验证 |

优先级不替代具体问题的影响评估。先关闭阻断项，无法关闭的风险必须说明影响、补偿措施和负责人；不能因为文档归档而默认接受。

## 如何推进

1. 选定当前问题或产品目标，查对应模块和契约。
2. 记录源码版本、工作树保护范围、所需环境和完成定义。
3. 按仓库规则进行最小实现与一次有针对性的验证。
4. 将结果回写 current；实现细节写模块，接口和数据写契约，过程证据留报告。
5. 需要发布时统一核对候选版本与制品，不能拼接不同版本的通过记录。

领域路线见[计划目录](README.md)，具体方案见[实施方案索引](../plans/README.md)。早期里程碑中的 `position`、BlockRelation、LangChain4j 配置和“恢复守卫”不是现行任务依据；现行数据、服务与网络边界以模块/契约为准。

## 验收限制

页面存在、视觉更新、命令行构建和历史通过记录均不能单独证明真实 Tauri、微信、真机或外部服务验收。当前未关闭项统一由问题登记维护，本文不复制另一套风险状态。

整理前的里程碑和顺序见[历史快照](../archive/maintenance-2026-11-15/planning/Overview.md)，仅供追溯。
