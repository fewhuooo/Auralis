## 目标

用同一套生成链处理教材和课件。INDEX 在连续原文中判断主题边界，同时为对应原文段生成短提要。ROUTE 利用全局提要组织目录，WRITER 按目录回读原文。预期改善三个具体问题：前言和正文混在同一块时误删正文，同一章被拆成多个顶层章节，以及目录收敛后小节内容过于粗略。

```text
单来源连续原文
  → INDEX 动态读窗、确认边界并生成段落提要
  → ROUTE 组织目录并绑定原文
  → WRITER 尽量整章输入、分节输出
  → 后端校验、组装和发布
```

当前源码已有页级 PDF/OCR 文本、幻灯片级 PPTX 文本及后端块内来源定位。现有 INDEX 按准备好的批次产出主题和摘要，ROUTE 消费主题目录，WRITER 已能合批写相邻小节。本次重构以动态读窗和原文段范围替换旧的主题及批次契约，写作输入改由最终节点绑定的范围决定。见[解析入口](../../Auralis-PC/src/services/documentParser/DocumentParser.ts)、[原文位置映射](../../Auralis-Server/src/main/java/com/auralis/app/ai/SourceChunkProvenance.java)和[生成服务](../../Auralis-Server/src/main/java/com/auralis/app/ai/OverviewGenerationService.java)。

## 设计复核结论

| 原方案还需要定清的边界 | 处理决定 |
| --- | --- |
| 提要写到了哪里，和小节结束在哪里是两个位置。 | 已提要位置可以向前走，同时保持 Segment 开放。窗口接缝给待判定位置留出右侧上下文。 |
| 找到一个很靠前的切点也可能导致大部分窗口反复送入。 | 每轮从较大的初始容量开始，找不到切点时由后端把当前目标容量翻倍。记录重复输入，作为后续对照策略的基线。 |
| 同一个 Segment 可能混有正文和辅文。 | INDEX 负责找出交界。混合内容未切开时，ROUTE 保留完整 Segment，避免误排正文。 |
| 整章能读进窗口，仍可能因输出篇幅而少写一节。 | 输入与输出分别估算。响应缺节或截断时按结果有效性处理，只有完整验证的正文才进入组装。 |
| 私有算法切换和公开结果是两条生命周期。 | 新任务只接续新版中间数据。已发布结果按保存时的快照读取。对尚在执行的旧任务，先隔离其发布权，再由现有终态机制收尾。 |

## 统一原文与段首定位

| 概念 | 职责 |
| --- | --- |
| `DocumentBlock` | 有序的解析原文单元，含来源、解析版本、顺序、文本和可取得的位置。PDF 保留页号，PPTX 保留幻灯片编号。标题等结构线索允许缺失。 |
| 段首摘录 | INDEX 返回的短原文。后端按顺序定位，将命中位置映射回原文 UTF-16 偏移。 |
| `Segment` | INDEX 确认的连续原文范围，携带主题、简短关键点和可确认的原文标题。同一个段可以跨页、跨幻灯片或跨窗口。 |
| `Section` | ROUTE 确定的展示小节，绑定一个或多个原文范围。章节或主题分组在其上组织。 |

所有范围采用同一来源版本下的半开区间 `[start, end)`。现有来源映射以解析块用 `LF` 拼接后的全局 `trim()` 文本为基准，字符位置沿用 Java 字符串的 UTF‑16 偏移。摘录的命中位置、回读片段和结果来源关联共享这一坐标。若输入经过检索 chunk 投影，按位置交集去重，重叠区必须对得上原文。窗口和 Segment 都以单份来源为边界，学科总览在 ROUTE 才汇总多份资料。可用文字缺少页码或元素定位时，保留已知的来源和范围。

结果装配时，后端将每节绑定的原文范围与生成快照中的同版本 chunk 相交，跨 chunk 的范围拆成多个引用。重叠 chunk 只认领尚未覆盖的字符，引用集合须连续覆盖相应原文范围。每个精确引用都带上 `sourceId`、来源版本、`chunkId`、`generation` 和该 chunk 能覆盖的绝对起止位置。块内位置仍由现有来源映射解析。版本已变化、范围存在缺口或超过公开引用容量时，返回明确错误。见[公开来源校验](../../Auralis-Server/src/main/java/com/auralis/app/ai/OverviewIdentityService.java)。

现有 OCR Sidecar 和解析产物即可支撑文字版。表格单元格、图示、备注等信息随解析产物实际提供的能力进入同一模型。图片里的教学内容未被解析到时，结果只能反映已取得的文字。解析层的块和用于检索的 chunk 可以有不同粒度。

### 容量续窗位置

窗口容量按已重建的 UTF-16 原文计算，可在任意完整 Unicode 字符后续读，包括单个 chunk 内部。句末或已有换行是模型判断自然切点的线索。

## INDEX 动态读窗与提要

### 窗口输入与输出

每个请求按原文顺序提供 `referenceText`、`originalText` 和 `lookaheadText` 三个相邻区间。中间区间用于定位和总结。`continuingSegment` 表示硬上限已提交打开段的前缀，`atCapacity` 和 `endOfDocument` 分别标识上限续读与末段收口。模型返回统一的 `segments`，首、尾和中间各项均提供该窗正文内的段首摘录和完整画像。

```json
{
  "segments": [
    {"startsWith": "数据模型的组成", "topic": "数据模型", "keyPoints": ["概念模型与逻辑模型的用途"], "sourceHeading": null, "role": "BODY"},
    {"startsWith": "1.2.6 关系模型\n关系模型的定义", "topic": "关系模型", "keyPoints": ["关系由属性和元组组成"], "sourceHeading": "1.2.6 关系模型", "role": "BODY"}
  ]
}
```

后端在可判定正文中忽略 Unicode 空白。首项必须匹配正文首个非空白字符，首项原文范围从窗口正文起点算起。后续项按顺序取前一切点之后的首处匹配。能在参考区找到或位置已越过的失配条目直接跳过，其余失配的画像可并入上一确认项，角色不一致时按正文保留。仅当 `continuingSegment` 为 true 时，响应还须包含顶层布尔 `startsNewSegment`。值为 true 表示旧段在提要前沿闭合，首项为新段。值为 false 表示首项为同一逻辑段的窗口内增量。切点或 EOF 闭合 Segment，原文标题经段首核对后保留。[分批实施文档](2026-11-10-overview-dynamic-window-implementation.md)

### 窗口如何推进

| 当前窗口的结果 | 下一窗或当前段的处理 |
| --- | --- |
| 普通窗口有确认切点 | 提交已闭合段。下一窗带上最多 256 个 UTF-16 代码单元的前侧参考，从未闭合尾段起点重读，并按初始目标容量补新原文。尾段已经超过初始目标时，仍尝试带上未闭合尾段及新原文，受实际容量上限约束。前窗的末项画像留待重读时替换。 |
| 无切点且还能容纳更多内容 | 保留待判定原文，把当前目标容量翻倍，以安全容量上限为封顶值，补入后续原文再判断。重复此过程，直到有切点、读到文档末尾或触及安全容量上限。 |
| 到达硬上限 | 窗口预先标出可提交提要的 `originalText`。已闭合段按切点提交，末项画像作为同一逻辑段的增量提交并推进提要前沿。最多 1024 个 UTF-16 代码单元留作下一窗的未决右侧原文。 |
| 后续遇到切点或文档结束 | 补齐仍未总结的原文范围，把按顺序暂存的提要合并为同一个 Segment 的提要，再交给 ROUTE。 |

例如前几窗已为 block 1–70 做过提要，后续确认 block 96 开始新节，就只补 71–95 的提要。ROUTE 收到的仍是 **1–95 一个 Segment**。上一窗已覆盖的重叠正文仅作为参考。窗口末尾尚需判断的位置保留在下一窗的可判定区，避免把真正的换节位置留在只读参考区。

提要在 INDEX 生成。常见路径由同一次 INDEX 调用完成边界和提要，容量上限场景也使用同一份原文坐标。运行状态记录已闭合段、打开段、已总结位置和待判定尾部。单个原文块就超过容量时，按块内位置分片送读，使用同一个 Segment 累积。达到上限后必须能继续前进，避免对同一窗口反复补发。

跨窗提要按原文顺序折叠。`topic` 以该段最早的有效主题为准，`sourceHeading` 只采用能在段起始原文核对的标题。后续提要追加 `keyPoints`，段中遇到的子标题也可记为要点。要点先统一首尾及重复空白，再按完全相同去重，保留首次出现的顺序。首版采用精确去重，避免误合并仅在条件、数值或否定词上有差异的要点。

三个位置要分开理解。**段起点**决定最后交给 ROUTE 的完整范围。**提要前沿**表示原文已经总结到哪里。**窗口末端**表示这次模型看到了哪里。正常续窗可以重读窗口末端以前的未决文字。上限续窗只提交到提要前沿，保留从提要前沿起的原文让下一窗判断。如果下一窗确认切点恰好等于提要前沿，直接用已有提要闭合，新增提要为空。只有段起点早于切点时才会生成 Segment。若恰好到文档末尾，使用末尾哨兵把最后一段闭合。空白尾部直接归入已确定的相邻范围，避免生成空节。

初始目标为 **65536 个 UTF-16 代码单元**，容量校验以实际发送的请求为准。扩窗前要能放下新原文，达到上限时提交已确认的提要范围。读到文档末尾时闭合最后一个实质段，尾随空白仍包含在来源范围内。现有调用追踪记录每窗的输入估算与输出预留。后续真实样本对照记录每窗新读和重复输入长度、切点数、扩窗次数、归章与排除、token 和耗时。

## ROUTE 目录与范围归属

ROUTE 消费有序 Segment 清单和可靠的目录线索。每个段提供原文范围、主题、关键点、原文标题及可用的辅文线索。ROUTE 把完整 Segment 唯一归入正文章节或附带理由的排除清单。原文起止位置由 INDEX 确定，ROUTE 按原样引用。章节级导读有实质教学内容时，应绑定到对应章节的可写节点。

- **教材**优先采用可验证的原书章、节层级。篇或部作为上位线索，正文中的直属编号节独立组织，实质章导言在同章内单列。目录里出现但资料正文未覆盖的章节仅供定位。
- **课件**可以直接按主题组织。连续讲同一个主题的多张幻灯片可以合为一节。生成的展示名称与原书标题分别标记。
- **段落用途**由 ROUTE 结合全局线索判断，INDEX 的角色是参考。整段前言、全书目录、篇首框架、出版、作者、致谢和行政材料按完整段排除，并记录可核对的理由。含实质教学内容的混合段和无法确认是否含教学内容的段完整归入正文，辅文与正文之间的切点由 INDEX 确定。
- **后端验收归属**时，对参与生成的每份来源检查合法区间及三类唯一归属。章和节的父子关系可聚合正文来源。

原文归属在 ROUTE 响应中只用完整 Segment ID 表示。后端从 INDEX 输出解析范围，校验每个 Segment 恰好出现一次，合并只接受同一来源中按原文顺序相邻的段。排除项附上出版信息、作者简介或行政安排等可核对的原因。最终目录至少应有一个具备原文范围的叶节点。归属是否恰当要结合源文检查。

ROUTE 优先一次看完整画像清单。超出容量时，按来源或原文连续组先得到局部规划，再由一份只含组名、章标题及少量线索的目录清单组织全局。跨组重新归章时保留已分配的原文范围和原始顺序。同一原书章被分到相邻组时，可以依有依据的章名归并。若紧凑目录仍超出预算，则给出容量错误。校验覆盖每个输入组，不能只发布装得下的前几个来源。

目录树是内部结构。第一版以现有公开章、节契约交付。只有一层主题的课件可以投影成一个以课件主题命名的容器，下面直接排列小节。更深的原书层级可以留作小节内部标题。这样可以区分真实原书层级和公开结果的展示包装。

## WRITER 整章阅读、分节交付

根据 ROUTE 的章节顺序打包原文。整章输入、提示开销和各节的预计输出都能放下时，一次请求可以处理整章，响应仍按稳定小节 ID 分开交付。整章放不下时，按相邻小节切批。单节过大时可以分批读写，再归并为同一节。

每个写作成员带上小节标题、分配的原文范围和篇幅目标。用原文中的定义、区分、条件、例子支撑正文。提要用于定位写作范围。相邻节作为参考时，分开标注各节的可写范围。原文只覆盖半节时，标明缺口。目录粒度和正文篇幅分别控制。例如「数据模型」在目录只占一节，正文仍能覆盖三要素、概念模型和原文例子。

对于分批写的超长单节，各批按原文范围生成互补正文，由程序按位置装配到同一节。需要统一用语时，将该节标题、术语约定和邻批的简短承接线索放入写作请求。按章、按节和节内拆批共用一种响应成员格式，例如 `[{memberId, bodyMarkdown}]`。后端将 `memberId` 映射回 `sectionId` 和原文范围。模型输出缺项、重复项、越权 ID 或被截断时，本批按错误类型进行有界修复或拆小。已提交的完整批次可以复用。组装时再核对最终目录中的每个小节都恰好有一份成稿。

节内拆批时，小节主标题由上层按 ROUTE 的小节标题渲染一次。模型在 `bodyMarkdown` 内从正文或更深的子标题开始，例如主标题是 `###` 时，正文可以用 `####`。各批只写自己负责的内容，需要全节小结时只安排在最后一批。装配时检查每个成员的首个非空行，仅剥离标题文本与当前小节主标题一致的重复 Markdown 标题，再用空行拼接正文。内部子标题、代码块和正文里的同名表述按原样保留。

后端检查应答成员齐全、每节正文有效、来源范围可验证，再按目录顺序组装。`OUTLINE` 交付现有目录和分节正文。`ALL` 在正文章节完成后另用一次 WRITER，按源序读取全部排除段原文，以及正文覆盖的章和节、提要及资料截止标记，提取阅读背景、结构和学习建议，区分全书导航与实际覆盖。版权、作者、致谢和行政信息不进入总导读。`SUMMARY` 继续表示独立短摘要。正式发布由后端组装。

## 直接替换与数据边界

Source 和 Subject 的详细总览统一走上述链路，覆盖直接 SSE 入口与持久后台任务。替换旧 INDEX 主题/批次输出、ROUTE 主题归属、WRITER 组输入及对应中间载荷的读写契约。清理被替代的详细生成分支和 `AURALIS_AI_OVERVIEW_ADAPTIVE_GENERATION_ENABLED` 选择开关。算法身份和私有中间格式一并更新，生成复用、断点、writer plan 和工作缓存按新身份取用。旧中间记录保留至既有留存期限，不转换或续跑。旧版本未完成任务通过现有终态机制结束并释放执行占用，保留历史记录和用量。重新发起生成进入新链路。

新链路继续受现有 Provider 准入、预算、取消、任务期限和来源版本保护。窗口检查点记录输入范围、打开段和已覆盖位置。一次响应整体验证通过后才提交推进状态。恢复后从已提交的边界继续，失败调用按现有已结算/未知派发规则处理。正文发布继续依赖已验证且完整的章节集合。

窗口检查点绑定来源、解析版本、算法与模型配置、可选候选位置集合及进入本窗前的状态指纹。响应通过校验后，已经闭合的段、暂存提要和新位置一起提交。恢复后先加载已提交状态，再重建对应窗口，避免已经推进的内容被重复总结。旧任务的清理以其当前租约和已派发调用为准。先阻止旧执行发布到新链路，账本按真实调用结算。旧任务可能遗留在待处理或恢复状态，直接入口和后台 Worker 都须能给出明确终态并释放占用。

现有正式结果继续按其保存的公开格式与 provenance 快照读取。它们作为已发布内容保留，新生成不会把这些内容或旧中间产物作为新 INDEX 的输入。重新生成仍从当前来源版本开始。默认采用现有持久化容器与公开响应形状，内部载荷版本更新。历史记录和原始资料的删除不属于这次重构。

## 验收依据

| 场景 | 通过条件 |
| --- | --- |
| `1.pdf` 的前言、目录和绪论 | 保留绪论正文开头，前言与目录从正文排除，总导读从前言提取有用的学习建议，从目录提取全书导航。1.1–1.3 同属第 1 章，1.2 和 1.3 的同页边界正确。1.3 截断处有明确说明，目录后续章节仅作导航。 |
| 无切点时的扩窗 | 后端逐次翻倍目标容量，每次补入新原文，容量封顶。找到切点或读到文档末尾即停止扩窗。 |
| INDEX 未切开的混合段 | ROUTE 保留完整 Segment，原文起止位置与 INDEX 输出一致。 |
| PPTX 多页延续同一主题 | 连续讲同一主题的幻灯片合为一节，确实换主题时切开。平铺目录和来源定位可核对。 |

质量验收以实际 Provider 返回的目录、正文和原文范围为准，分别记录切点准确性、归章、排除、写作覆盖、输入输出 token 和总耗时。已有的 `1.pdf` 直连试验可作为基线。补充层级规则后模型能归对绪论，但出现正文开头被整块排除和 1.2 范围过长。单写 1.2 输出约 2,746 token，说明按章打包必须把输出成本一起算进去。直连结果只说明单份样本上的表现，跨窗恢复与 PC 正式采纳另按实际链路验证。
