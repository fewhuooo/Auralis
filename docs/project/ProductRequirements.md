# Auralis 产品需求

更新时间：2026-08-24

文档状态：现行需求

权威范围：产品目标、用户、功能范围、跨端职责、非功能要求与产品验收条件

事实来源：已确认的 Auralis 产品方向、当前三端功能边界与现行代码能力

## 产品目标

Auralis 旨在把学习资料、知识理解、任务执行、复习反馈和多端同步组织成一个连续工作流：

```text
资料或想法进入
→ 归入学科与资产
→ 提炼知识块和任务块
→ 排期、专注与复习
→ 统计反馈
→ 多端同步与继续处理
```

产品不以“页面数量”作为完成标准，而以用户是否能安全、连续地完成上述闭环作为验收依据。

## 目标用户

- 需要同时处理课程资料、知识理解和学习任务的学生。
- 需要在电脑、手机和平板之间切换的多设备用户。
- 希望利用 AI 做资料摄入、问答、提炼、任务抽取和排期建议的学习者。
- 需要离线或弱网下继续记录，并在恢复网络后同步的用户。

## 核心原则

- **学科作为主要上下文**：资料、知识、任务、AI 对话和复习尽量有明确学科归属。
- **块作为核心数据单元**：知识块与任务块可独立创建、更新、同步和关联。
- **本地优先**：客户端可先本地操作，再通过 mutation 和 cursor 增量同步。
- **跨端分工**：不强求三端页面完全相同，而要求核心数据语义一致。
- **AI 可追溯**：AI 结果应保留来源上下文，用户能判断、修改和继续使用。
- **安全隔离**：用户数据、资产、同步记录和长连接必须按用户隔离。

## 核心场景

### 场景 1：资料进入知识工作区

用户上传文件或录入内容，将其绑定到学科；系统解析内容并允许用户阅读、提炼、标注、总结或转成知识块。

验收要点：

- 上传对象只能绑定到当前用户。
- 文件状态可查询，失败时有可理解反馈。
- AI 摄入与提炼的来源可追溯。
- 未完成的对象校验不得被写成已安全验收。

### 场景 2：从知识生成行动

用户从资料、AI 输出或手工输入中形成任务，设置学科、时长、负荷、状态和排期，再进入专注流程。

验收要点：

- 任务字段在客户端、API、数据库和同步链路中一致。
- 删除后不会在冷启动或其他端重新出现。
- 排期、专注和完成状态能形成连续操作。

### 场景 3：多端继续工作

用户在一个端产生或修改数据，在其他端恢复同一用户上下文，并正确处理增量、冷启动、断网和冲突。

验收要点：

- 所有同步数据带用户隔离。
- access/refresh token 用途严格区分。
- WebSocket 断连、token 过期和心跳行为可验证。
- 直接 CRUD 与 mutation 删除采用一致语义。

### 场景 4：复习与反馈

用户查看待复习内容、完成专注或任务，并从统计中了解近期投入与完成情况。

验收要点：

- 统计数据来源明确，不把 mock 或本地占位数据当成服务端事实。
- 复习、专注和统计之间的状态转换可追溯。

## 功能范围

### 账号与权限

- 注册、登录、access token、refresh token 刷新。
- 旧明文密码登录后迁移为 BCrypt。
- 普通 API 拒绝 refresh token。
- PC、Mobile 和 WebSocket 使用一致的用户身份语义。

### 学科空间

- 创建和进入学科上下文。
- 在学科内组织文件、知识、任务和 AI 操作。
- PC 与 Tablet 提供适合大屏的工作区，Mobile 提供快速入口。

### 知识块

- 创建、查询、更新、删除和同步。
- 保存主题、标题、摘要、来源、颜色、版本、软删除和可选加密载荷。
- 支持块关系和 AI 摄入结果关联。

### 任务块

- 创建、查询、更新、删除和同步。
- 保存名称、描述、学科、时长、负荷、状态、排期、版本和软删除。
- 支持时间线、专注和统计使用。

### 资产与文件

- 获取 MinIO 预签名上传地址。
- 上传后绑定当前用户资产。
- 查询资产和处理状态。
- 解析文件并进入 AI/RAG 流程。

### AI / RAG

- 普通与流式聊天。
- PC Tauri 对当前可预览文件执行本地原生提取或 OCR，并向服务端提交统一解析结果；PC Web 不作为发布目标。
- Office 文件即使未在可见预览中打开，也必须可由 PC Tauri 的后台解析任务处理；仅能预览但无法稳定提取或 OCR 的格式不能标记为 AI READY。
- Mobile/Tablet 可以继续上传和查看原文件，但本期不在端侧解析；此类 FILE 在同一用户的 PC Tauri 完成解析前保持等待状态。
- 文件检索默认限定当前 Source，证据不足或用户明确跨文件时只扩大到当前 Subject。
- 原生文本选区可用于解释、提问或创建知识块；图片和扫描 PDF 不生成 OCR 文本覆盖层。
- AI 回答只向用户展示来源文件名；保存为知识块前必须允许用户确认并编辑内容。
- 任务抽取、手写转换和排期建议。
- 使用向量库检索学科或来源上下文。

AI 输出属于辅助结果，用户必须能识别失败、超时和非结构化结果；不把模型回答当作不可修改的业务事实。

### 同步与长连接

- mutation push、cursor pull、冷启动数据返回。
- WebSocket 同步事件与文档解析通知。
- 心跳、token 更新、过期审计和断连策略。

### 端侧体验

- PC：仪表盘、学科大厅、学科工作区、资产、时间线、个人设置。
- Mobile：启动分流、首页、专注、AI、统计、设置、登录、时间线、复习、资产、个人资料、手写。
- Tablet：仪表盘、学科大厅、工作区、手写、专注、复习、个人资料、AI、登录。

## 跨端职责

| 能力 | PC | Mobile | Tablet |
| --- | --- | --- | --- |
| 快速捕获 | 支持 | 主要入口 | 支持 |
| 文件阅读与组织 | 主要入口 | 轻量入口 | 主要入口 |
| 手写与批注 | 非核心 | 轻量手写 | 大屏重点，但入口可受开关控制 |
| 任务排期 | 重型编排 | 快速编辑 | 大屏编排 |
| 专注与复习 | 查看和管理 | 高频执行 | 执行与回顾 |
| AI | 工作区伴读与整理 | 随身问答 | 文件上下文伴读 |

## 非功能要求

### 安全

- 用户数据必须按认证用户隔离。
- 生产密钥和密码必须通过环境变量或密钥管理注入。
- 上传绑定必须验证对象归属、存在性、大小和类型。
- ParsedDocument 必须同时验证当前 Source revision、原 Asset 内容哈希和用户归属；多设备迟到结果不能覆盖已接受结果。
- 客户端不得覆盖服务端 AI key 或 base URL。

### 可靠性

- 删除语义在 CRUD、mutation 和冷启动中一致。
- 弱网、断线、token 过期和重试有明确反馈。
- 本地数据和远程数据的权威关系明确。
- 数据库变化应有可重复迁移与回滚方案。

### 性能与体验

- 首屏、路由切换和大屏多栏交互避免明显闪烁与阻塞。
- 长文档、PDF、图表和手写画布在目标设备上可操作。
- AI、上传和同步的长耗时操作展示进度与错误。
- Windows MSI 必须离线包含 OCR Sidecar、Runtime、模型和许可证；安装包体积、模型预热、标准页耗时和峰值内存必须先测量并形成回归预算。

### 可维护性

- 模块、API、字段和文档各有唯一权威来源。
- 关键安全、同步和数据路径有自动化测试。
- 构建、部署、备份和恢复有可重复步骤。

## 当前里程碑范围

当前优先级是把账号、资产、知识块、任务块、同步和多端主流程验证闭环，并在 Windows x64 PC Tauri 完成当前文件 AI 辅助阅读闭环，再恢复或扩大增强能力。Tablet 手写代码可以保留，但 Tablet 端 OCR/深度阅读不应先于核心数据安全和同步可靠性进入发布门禁。

## 首个候选版本范围（2026-08-16）

首个候选版本面向以下目标端：Windows x64 PC Tauri、Mobile H5、微信小程序和 Tablet 主工作区。PC Web 已退出发布目标，Vite Web 运行方式只作为 Tauri 内部开发工具。四个目标端共享同一套用户、资料、知识、任务、同步、复习、统计和 AI 语义；页面形态和端侧职责可以不同。AI 辅助阅读的本地解析与 OCR 首期只在 PC Tauri 交付；Tablet 手写笔记可以保留在端内，但不进入本候选版本的云同步主流程。

候选版本的主流程验收结果和责任角色如下：

| 主流程 | 候选版本验收结果 | 责任角色 |
| --- | --- | --- |
| 注册登录 | 能注册、登录、刷新、退出；受保护页面拒绝未登录访问；用户、设备和会话边界可验证 | 产品/业务验收、后端、QA/发布 |
| 资料上传 | 能创建上传意图、完成对象绑定并查询处理状态；对象归属、存在性、大小、类型和失败反馈可验证 | 后端/基础设施、PC/Tauri、Mobile/Tablet、QA/发布 |
| 学习工作区 | 能进入学科，组织资料，创建或修改知识块与任务块，并在 PC/Tauri、Tablet 主工作区和 Mobile 快速入口中继续处理 | 产品/业务验收、各端负责人、后端 |
| 同步 | 能执行 push、pull、冷启动恢复、幂等重试、版本冲突和软删除语义；多端使用同一用户边界 | 后端、各端负责人、QA/发布 |
| 复习 | 能查看 due 内容、提交评分或 SKIP，并保持状态回放与重复请求幂等 | 产品/业务验收、后端、Mobile/Tablet |
| 统计 | 能展示服务端来源的任务完成和复习统计，完成日期与业务状态转换一致 | 产品/业务验收、后端、各端负责人 |
| AI 对话 | 能进行普通或流式对话，展示失败/超时；PC 当前文件检索可按确定性规则静默扩大到当前学科，且只显示来源文件名；AI 结果经用户确认后才能保存为知识块 | 产品/业务验收、后端/基础设施、PC/Tauri、QA/发布 |

责任角色不代表个人验收已经完成：代码存在、自动测试、真实依赖联调和 GUI/真机人工验收必须分别记录证据。候选版本范围外继续保持：Tablet 手写笔记云同步、微信之外的其它小程序平台、旧 Server 数据自动迁移、跨实例事件 Broker、AI 自动执行领域写操作。

## 明确非目标

- 不要求三个客户端页面完全一致。
- 不把所有平台的 Uni-app 构建脚本存在视为全部平台已支持。
- 不把 AI 生成内容当作自动正确的最终结论。
- 不在缺少测试与人工证据时宣称生产就绪。
- 不依据历史 StudyCore 需求恢复已删除功能。

## 产品验收条件

发布前至少必须满足：

1. 登录、刷新、退出和未登录访问行为已验证。
2. 知识块、任务块和资产均通过跨用户隔离测试。
3. 直接删除与同步删除语义一致，冷启动不恢复已删除数据。
4. 上传对象存在性、大小、类型和归属校验闭环。
5. WebSocket 握手、心跳、token 过期和断连有自动或人工证据。
6. PC Tauri、后端、Mobile H5 与微信构建通过；Windows x64 正式安装包、开发者工具和目标真机另行验收，PC Web 不作为发布门禁。
7. 生产密钥、默认密码、备份、恢复、监控和发布回滚满足运维门禁。
8. 所有已知 P1 问题关闭，P2 问题有明确接受或延期决定。
